# SPEC-012-01 — Payer une commande téléphonique par Airtel Money

## Comportement observable

- `POST /v1/admin/phone-orders` accepte `payment` : `{ method: 'on_delivery' }` (défaut) ou `{ method: 'wallet', providerCode, transactionRef? }`. Réponse : en plus de FEAT-011, `payment: { method, instructions }`, `transfer?` (`paid` | `pending` | `amount_mismatch`) et `deliveryCode` (SPEC-012-02).
- `POST /v1/admin/phone-orders/:orderId/transfer` `{ transactionRef }` → `{ transfer, order }`.
- Écran `/admin/phone-order` : section « 4. Le paiement », écran de résultat avec le code, l'état du paiement et la vérification du numéro.

## Règles métier

- R1 — Le moyen est choisi par capacité : `matchedByTransferReceipt` et le `providerCode` demandé pour `wallet`, `collectedOnDelivery` sinon.
- R2 — Le paiement wallet est créé avec `payerPhone` = numéro de l'appelant : le transfert doit venir de ce téléphone (contrôle de l'expéditeur, FEAT-009).
- R3 — Le numéro de transaction passe par le même rapprochement que dans l'app (`MobileMoneyReceiptsService.claim`).
- R4 — Tant que le transfert n'est pas rapproché, la commande reste `awaiting_payment` (et expire comme toute commande impayée).

## Scénarios

### SPEC-012-01-SC01 — Airtel pendant l'appel

Critères : FEAT-012-AC03

- **Étant donné** un appelant qui veut payer par Airtel
- **Quand** le standardiste envoie la commande sans numéro de transaction
- **Alors** un paiement Airtel est créé au téléphone de l'appelant, les consignes sont renvoyées, aucun rapprochement n'est tenté

### SPEC-012-01-SC02 — l'appelant a déjà payé

Critères : FEAT-012-AC03

- **Étant donné** un appelant qui lit son numéro de transaction
- **Quand** le standardiste le saisit avec la commande
- **Alors** le numéro est vérifié aussitôt et le résultat renvoyé

### SPEC-012-01-SC03 — Airtel non activé

Critères : FEAT-012-AC03

- **Étant donné** Airtel non activé pour ce restaurant
- **Quand** le standardiste choisit Airtel
- **Alors** 409 `PAYMENT_METHOD_UNAVAILABLE`, aucun paiement

### SPEC-012-01-SC04 — numéro donné après l'appel

Critères : FEAT-012-AC03

- **Étant donné** une commande Airtel en attente
- **Quand** le standardiste saisit le numéro plus tard
- **Alors** le rapprochement est fait sur le paiement Airtel de cette commande

### SPEC-012-01-SC05 — écran [evidence: manual]

Critères : FEAT-012-AC05

- **Étant donné** le standardiste connecté
- **Quand** il choisit Airtel, envoie, puis vérifie le numéro lu par le client
- **Alors** il voit le code, puis « Paiement Airtel Money reçu » ; voir `e2e-demo.md`

## Erreurs et cas limites

Montant différent : `amount_mismatch` affiché. Aucun paiement wallet sur la commande : 404.
