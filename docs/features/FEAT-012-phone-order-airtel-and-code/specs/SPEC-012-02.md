# SPEC-012-02 — Code de livraison choisi pendant l'appel

## Comportement observable

- Toute commande par téléphone renvoie `deliveryCode` (4 chiffres), le même à chaque nouvel envoi.
- Au moment où le livreur récupère la commande, c'est ce code qui est émis (au lieu d'un code tiré au hasard) ; `deliver` exige ce code.

## Règles métier

- R1 — Table `delivery_code_presets` (module `deliveries`) : empreinte + valeur chiffrée, jamais en clair ; une ligne par commande.
- R2 — Le code n'est jamais renvoyé au livreur ; la vérification (empreinte, usage unique, expiration) est inchangée.
- R3 — Le code n'est pas gardé dans l'enregistrement d'idempotence (stocké en base) : il est redemandé, et `presetDeliveryCode` renvoie le même.

## Scénarios

### SPEC-012-02-SC01 — le code donné est celui demandé à la porte

Critères : FEAT-012-AC04

- **Étant donné** un code choisi pour la commande
- **Quand** le livreur la récupère
- **Alors** le code émis est ce code, stocké sous forme d'empreinte, et lisible par le client propriétaire

### SPEC-012-02-SC02 — sans code choisi, rien ne change

Critères : FEAT-012-AC04

- **Étant donné** une commande de l'app
- **Quand** le livreur la récupère
- **Alors** un code aléatoire est émis comme avant

## Erreurs et cas limites

Deux demandes simultanées : la seconde renvoie le code de la première (clé primaire).
