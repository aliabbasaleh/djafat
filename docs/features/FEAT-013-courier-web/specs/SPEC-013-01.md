# SPEC-013-01 — Construire et faire tourner l'app livreur sur le web

## Comportement observable

- `pnpm --filter @djafat/courier build:web` écrit `apps/courier/dist-web/` (ignoré par Git).
- Ouverte dans un navigateur, l'app livreur se comporte comme sur téléphone.

## Règles métier

- R1 — Stockage de session : sur `web`, `localStorage` (même choix que les autres fronts web du dépôt) ; ailleurs, `expo-secure-store`. Le choix est fait à un seul endroit.
- R2 — Un stockage indisponible (navigation privée, quota) n'empêche pas l'app de démarrer : la session est simplement absente.
- R3 — Arrêter le suivi GPS ne fait jamais planter l'écran (déjà livré, `stop()` dans `lib/location.ts`).

## Scénarios

### SPEC-013-01-SC01 — session sur le web

Critères : FEAT-013-AC02

- **Étant donné** la plateforme `web`
- **Quand** une session est enregistrée, relue puis effacée
- **Alors** elle passe par le stockage du navigateur, et l'effacement la retire

### SPEC-013-01-SC02 — session sur téléphone

Critères : FEAT-013-AC02

- **Étant donné** la plateforme `android`
- **Quand** une session est enregistrée
- **Alors** elle passe par le coffre sécurisé, jamais par le stockage du navigateur

### SPEC-013-01-SC03 — stockage indisponible

Critères : FEAT-013-AC02

- **Étant donné** un stockage du navigateur qui lève une erreur
- **Quand** l'app relit la session
- **Alors** elle obtient « pas de session », sans plantage

### SPEC-013-01-SC04 — parcours réel dans un navigateur [evidence: manual]

Critères : FEAT-013-AC01, FEAT-013-AC03, FEAT-013-AC04

- **Étant donné** la construction web servie et l'API réelle
- **Quand** un livreur fait tout le parcours dans le navigateur
- **Alors** la commande est livrée ; la construction iOS/Android passe toujours. Voir `e2e-demo.md`

## Erreurs et cas limites

GPS refusé par le navigateur : la position n'est pas envoyée (comportement existant du téléphone).
