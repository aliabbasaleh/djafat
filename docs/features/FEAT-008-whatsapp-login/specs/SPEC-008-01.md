# SPEC-008-01 — Registre des méthodes de connexion et SMS désactivable

## Comportement observable

- `GET /v1/auth/methods` (public) répond 200 :
  `{ methods: [ { id: 'whatsapp', available, link? }, { id: 'sms', available }, { id: 'email', available } ] }`,
  dans l'ordre de préférence au Tchad. `link` n'est présent que si WhatsApp est disponible :
  `https://wa.me/<numéro DJAFAT sans +>?text=Code%20DJAFAT`.
- `SMS_PROVIDER=disabled` : `POST /v1/auth/otp/request` répond 503 `SMS_UNAVAILABLE`, et `sms` est `available: false`.

## Règles métier

- R1 — Une méthode est disponible si son transport est réel (`SMS_PROVIDER=http`, `EMAIL_PROVIDER=smtp`, `WHATSAPP_PROVIDER=cloud`) ou si c'est un faux hors production. WhatsApp exige en plus `WHATSAPP_BUSINESS_NUMBER` (sinon pas de lien possible).
- R2 — En production, `SMS_PROVIDER=mock` reste refusé au démarrage (règle FEAT-006, inchangée).
- R3 — En production, `SMS_PROVIDER=disabled` n'est accepté que si `WHATSAPP_PROVIDER=cloud` : sinon aucun client ne pourrait se connecter par téléphone.
- R4 — `WHATSAPP_PROVIDER=cloud` exige `WHATSAPP_ACCESS_TOKEN`, `WHATSAPP_PHONE_NUMBER_ID`, `WHATSAPP_APP_SECRET`, `WHATSAPP_VERIFY_TOKEN` et `WHATSAPP_BUSINESS_NUMBER`.
- R5 — Une nouvelle méthode (Facebook, Apple, Google…) s'ajoute comme une nouvelle entrée du registre, sans changer le format de la réponse.

## Scénarios

### SPEC-008-01-SC01 — tout configuré : trois méthodes disponibles, lien WhatsApp

Critères : FEAT-008-AC01

- **Étant donné** WhatsApp Cloud, SMS par passerelle et SMTP configurés, numéro DJAFAT `+23560000001`
- **Quand** les méthodes sont demandées
- **Alors** la réponse liste `whatsapp`, `sms`, `email` dans cet ordre, toutes disponibles, et le lien WhatsApp est `https://wa.me/23560000001?text=Code%20DJAFAT`

### SPEC-008-01-SC02 — lancement sans SMS : SMS indisponible, pas de lien sans numéro

Critères : FEAT-008-AC01, FEAT-008-AC02

- **Étant donné** la production avec `SMS_PROVIDER=disabled`, WhatsApp Cloud configuré et e-mail en faux ; puis un environnement de développement sans `WHATSAPP_BUSINESS_NUMBER`
- **Quand** les méthodes sont demandées
- **Alors** en production `sms` et `email` sont indisponibles et `whatsapp` disponible ; en développement sans numéro, `whatsapp` est indisponible et n'a pas de lien

### SPEC-008-01-SC03 — demande de code SMS avec le SMS coupé

Critères : FEAT-008-AC02

- **Étant donné** `SMS_PROVIDER=disabled`
- **Quand** un code SMS est envoyé
- **Alors** l'envoi échoue en 503 `SMS_UNAVAILABLE`

### SPEC-008-01-SC04 — cohérence de la configuration en production

Critères : FEAT-008-AC02

- **Étant donné** la production
- **Quand** la configuration est `SMS_PROVIDER=disabled` sans WhatsApp Cloud, puis `disabled` avec WhatsApp Cloud complet, puis WhatsApp Cloud sans jeton
- **Alors** le premier cas est refusé, le deuxième accepté, le troisième refusé en nommant `WHATSAPP_ACCESS_TOKEN`

### SPEC-008-01-SC05 — SMS coupé : refus immédiat, sans quota consommé ni code créé

Critères : FEAT-008-AC02

- **Étant donné** `SMS_PROVIDER=disabled`
- **Quand** un code SMS est demandé pour un numéro
- **Alors** la demande échoue en 503 `SMS_UNAVAILABLE` avant toute limite de débit et sans code enregistré, pour que des demandes SMS ne puissent pas épuiser le quota WhatsApp partagé du numéro (trouvé pendant la démonstration de bout en bout)

## Erreurs et cas limites

Le registre ne révèle aucun secret : seulement l'identifiant, la disponibilité et le lien public.

## Contrats API et données

Route **nouvelle** : `GET /v1/auth/methods`. Code d'erreur **nouveau** : `SMS_UNAVAILABLE`. Variables **nouvelles** : `WHATSAPP_*`, valeur `disabled` pour `SMS_PROVIDER`.
