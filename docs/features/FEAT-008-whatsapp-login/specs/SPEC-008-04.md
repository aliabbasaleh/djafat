# SPEC-008-04 — Envoyer le code par l'API WhatsApp Cloud

## Comportement observable

Le transport `whatsapp` de `OtpDeliveryPort` envoie la réponse au client :
`POST {WHATSAPP_GRAPH_URL}/{WHATSAPP_PHONE_NUMBER_ID}/messages`,
`Authorization: Bearer WHATSAPP_ACCESS_TOKEN`,
`{ messaging_product: 'whatsapp', to: '<chiffres>', type: 'text', text: { body } }`.

## Règles métier

- R1 — Le texte donne le code, sa durée, et avertit de ne le donner à personne, même à quelqu'un qui dit être de DJAFAT ou livreur.
- R2 — Délai de 5 s par tentative ; une seule nouvelle tentative sur erreur réseau, délai dépassé ou 5xx ; pas de nouvelle tentative sur 4xx.
- R3 — Échec final → 503 `OTP_DELIVERY_FAILED`, journalisé sans code, sans jeton et avec le numéro masqué.
- R4 — Faux (`WHATSAPP_PROVIDER=mock`) hors production : le code est lisible dans Redis sous `otp:mock:whatsapp:<numéro>`, avec la même durée ; en production : 503 `WHATSAPP_UNAVAILABLE`.

## Scénarios

### SPEC-008-04-SC01 — envoi accepté

Critères : FEAT-008-AC06

- **Étant donné** une API Graph locale qui répond 200
- **Quand** un code est envoyé à `+23566123456`
- **Alors** elle reçoit une requête authentifiée vers `/<phone_number_id>/messages` avec `to: '23566123456'` et un texte contenant le code et l'avertissement

### SPEC-008-04-SC02 — erreur 5xx puis succès : une nouvelle tentative

Critères : FEAT-008-AC06

- **Étant donné** une API qui répond 500 puis 200
- **Quand** un code est envoyé
- **Alors** l'envoi réussit après exactement 2 requêtes

### SPEC-008-04-SC03 — refus 4xx : pas de nouvelle tentative, 503, rien de secret dans les journaux

Critères : FEAT-008-AC06

- **Étant donné** une API qui répond 401
- **Quand** un code est envoyé
- **Alors** l'envoi échoue en 503 `OTP_DELIVERY_FAILED` après 1 requête, et les journaux ne contiennent ni le code, ni le jeton, ni le numéro complet

### SPEC-008-04-SC04 — faux WhatsApp

Critères : FEAT-008-AC06

- **Étant donné** le faux en développement, puis en production
- **Quand** un code est envoyé
- **Alors** en développement le code est lisible dans Redis ; en production l'envoi échoue en 503 `WHATSAPP_UNAVAILABLE`

## Erreurs et cas limites

Le corps de la réponse Graph n'est jamais journalisé.

## Contrats API et données

Variables **nouvelles** : `WHATSAPP_PROVIDER` (`mock` | `cloud`), `WHATSAPP_GRAPH_URL` (par défaut `https://graph.facebook.com/v21.0`), `WHATSAPP_ACCESS_TOKEN`, `WHATSAPP_PHONE_NUMBER_ID`, `WHATSAPP_APP_SECRET`, `WHATSAPP_VERIFY_TOKEN`, `WHATSAPP_BUSINESS_NUMBER`, `WHATSAPP_MAX_CODES_PER_HOUR`.
