# SPEC-020-07 — Le bouton « Compte », la page `/compte` et l'inscription sur le site

## Comportement observable

Aujourd'hui, déconnecté, l'en-tête montre « Connexion » vers `/connexion`
(`apps/web/src/components/CartIndicator.tsx:46-52`). Cette page propose des onglets WhatsApp, SMS,
e-mail parmi les seuls canaux disponibles, puis un code (`apps/web/src/app/connexion/page.tsx:53-256`).
Neuf appels redirigent vers `/connexion?redirect=…` (voir l'intake dans `progress.md`).

Après la spec :

- l'en-tête déconnecté montre « 👤 Compte » vers `/compte` ; connecté, il ne change pas ;
- `/compte` porte le titre « Mon compte » et deux onglets, « Se connecter » (par défaut) et
  « Créer un compte » (`?onglet=inscription` ouvre le second) ;
- `/connexion?redirect=X` redirige vers `/compte?redirect=X` ; les liens internes visent `/compte` ;
- l'onglet « Créer un compte » mène, par le code reçu, à un compte ouvert.

La connexion elle-même (mot de passe, nouvel appareil, mot de passe oublié) est l'objet de
SPEC-020-10.

## Règles métier

- R1 — Onglet « Se connecter » (FEAT-020-VIS01), dans cet ordre : E-mail ; Mot de passe avec un bouton afficher/masquer ; bouton « Se connecter » ; lien « Mot de passe oublié ? » ; séparateur « ou recevoir un code » ; trois boutons de canal : « ✉️ E-mail », « WhatsApp », « SMS ».
- R2 — Un canal que `GET /auth/methods` déclare indisponible est un bouton désactivé portant « Bientôt disponible » ; un canal disponible ouvre son parcours par code : e-mail (`/auth/email/request` puis `/verify`), WhatsApp et SMS (parcours actuels de FEAT-008 et FEAT-006). Si `/auth/methods` échoue, seul l'e-mail est proposé.
- R3 — Onglet « Créer un compte » (FEAT-020-VIS02), dans cet ordre : Nom complet ; Numéro de téléphone ; E-mail ; Mot de passe (aide « 8 caractères minimum ») ; Confirmer le mot de passe ; bouton « Créer mon compte » ; phrase « Un code de confirmation sera envoyé à votre adresse e-mail. »
- R4 — Avant l'envoi, l'écran vérifie : champs remplis, confirmation identique (« Les mots de passe ne correspondent pas. »), règle du mot de passe de SPEC-020-02. Après l'envoi, chaque erreur de l'API s'affiche sous son champ : les chemins d'un 422, `PHONE_ALREADY_USED` sous le téléphone avec un lien « Se connecter ».
- R5 — Après « Créer mon compte » : l'étape du code de FEAT-020-VIS03 (titre « Vérifiez votre e-mail », adresse masquée, durée de validité, « Code à 6 chiffres », « Vérifier », « Renvoyer le code » inactif 60 s avec décompte, « Retour »), sans la case « Se souvenir de cet appareil » : l'appareil est mémorisé d'office. Le bon code connecte le client (stockage et redirection : SPEC-020-10 R4).

## Scénarios

### SPEC-020-07-SC01 — « Compte » dans l'en-tête et la page à deux onglets [evidence: manual]

Critères : FEAT-020-AC01

- **Étant donné** un visiteur déconnecté sur `/`, en 390×844
- **Quand** il clique sur « 👤 Compte »
- **Alors** `/compte` s'ouvre avec « Mon compte », l'onglet « Se connecter » actif et l'onglet « Créer un compte », conformes à FEAT-020-VIS01

### SPEC-020-07-SC02 — ancienne adresse redirigée, redirection sûre

Critères : FEAT-020-AC01

- **Étant donné** les cibles `/panier`, `/commandes/abc`, `//evil.example`, `https://evil.example` et rien
- **Quand** la destination après connexion et l'adresse de `/connexion?redirect=…` sont calculées
- **Alors** les deux premières sont gardées, les trois autres deviennent `/` ; `/connexion?redirect=%2Fpanier` mène à `/compte?redirect=%2Fpanier`

### SPEC-020-07-SC03 — contrôles du formulaire d'inscription

Critères : FEAT-020-AC02

- **Étant donné** un nom vide, puis une confirmation différente, puis « motdepasse »
- **Quand** le formulaire est validé avant l'envoi
- **Alors** l'erreur va sous « Nom complet », puis sous « Confirmer le mot de passe », puis sous « Mot de passe »

### SPEC-020-07-SC04 — erreurs de l'API sous leur champ

Critères : FEAT-020-AC02, FEAT-020-AC04

- **Étant donné** une réponse 422 avec les chemins `email` et `password`, puis une réponse 409 `PHONE_ALREADY_USED`
- **Quand** elles sont traduites pour le formulaire
- **Alors** les messages vont sous E-mail et Mot de passe, puis sous Numéro de téléphone

### SPEC-020-07-SC05 — canaux actifs et « Bientôt disponible »

Critères : FEAT-020-AC09, FEAT-020-AC08

- **Étant donné** `GET /auth/methods` qui déclare l'e-mail disponible, WhatsApp et SMS indisponibles ; puis les trois disponibles ; puis un échec de l'appel
- **Quand** les boutons de canal sont calculés
- **Alors** e-mail actif et les deux autres désactivés « Bientôt disponible » ; puis les trois actifs ; puis l'e-mail seul

### SPEC-020-07-SC06 — créer un compte dans un navigateur [evidence: manual]

Critères : FEAT-020-AC03, FEAT-020-AC02

- **Étant donné** le site et l'API locaux, avec le faux envoi d'e-mails
- **Quand** un visiteur remplit « Créer un compte », reçoit le code et le saisit
- **Alors** l'étape du code est conforme à FEAT-020-VIS03, et le visiteur arrive connecté, son prénom dans l'en-tête ; captures dans `assets/exec-*`

## Erreurs et cas limites

- Stockage du navigateur bloqué (navigation privée stricte) : comme aujourd'hui, la session ne
  tient pas (`apps/web/src/lib/auth-storage.ts:54-64`).
- Double clic sur « Créer mon compte » : le bouton est en chargement, un seul envoi.

## Contrats API et données

Aucun contrat nouveau côté site : il appelle les routes de SPEC-020-03 par `@djafat/sdk`
(méthodes _nouvelles_ de `createAuthClient`, `packages/sdk/src/auth.ts:48-117`).

## Autorisations

Page publique ; connecté, `/compte` renvoie vers `redirect` ou `/`.

## UI et accessibilité

- Onglets : composant `Tabs` de `@djafat/ui` (`packages/ui/src/navigation/Tabs.tsx`, rôle
  `tablist`, flèches, Début, Fin), panneaux `tabpanel` liés.
- Champs : composant `Input` (libellé obligatoire, erreur en `role="alert"` reliée par
  `aria-describedby`, `packages/ui/src/form/Input.tsx`) ; `autocomplete` `name`, `tel`, `email`,
  `new-password`, `one-time-code`.
- Canal indisponible : `disabled` et texte « Bientôt disponible » lisible (pas seulement la couleur).
- Libellés en français, comme le reste du site.

## Références visuelles

- FEAT-020-VIS01 : ordre et présence des éléments de R1 et R2 (SC01, SC05).
- FEAT-020-VIS02 : ordre et présence des champs de R3 (SC03).
- FEAT-020-VIS03 : éléments de l'étape du code, R5 (SC06).
  Aucune taille, couleur ni marge n'est fixée par ces maquettes : celles du kit `@djafat/ui`
  s'appliquent.
