# SPEC-020-10 — Se connecter sur le site : mot de passe, nouvel appareil, mot de passe oublié

## Comportement observable

Aujourd'hui la page de connexion du site n'enchaîne que « demander un code » puis « saisir le
code » (`apps/web/src/app/connexion/page.tsx:87-147`), avec un message par cause d'erreur
(`page.tsx:22-36`). La session est gardée dans `localStorage` (`apps/web/src/lib/auth-storage.ts:10-64`).

Après la spec, l'onglet « Se connecter » de `/compte` (SPEC-020-07 R1) connecte par mot de passe,
demande le code d'un nouvel appareil, et propose « Mot de passe oublié ? ».

## Règles métier

- R1 — « Se connecter » envoie e-mail, mot de passe et le jeton d'appareil gardé par ce navigateur. `signed_in` : connecté. `code_required` : l'étape du code (FEAT-020-VIS03) avec la destination masquée, la case « Se souvenir de cet appareil » cochée par défaut, et le choix du canal si plusieurs sont utilisables (indisponibles « Bientôt disponible »).
- R2 — « Renvoyer le code » est inactif 60 s avec le décompte ; « Retour » revient au formulaire.
- R3 — « Mot de passe oublié ? » : e-mail, puis l'étape du code avec « Nouveau mot de passe » et « Confirmer le mot de passe » ; la confirmation et la règle de SPEC-020-02 sont vérifiées avant l'envoi.
- R4 — Une fois connecté (ici, après une inscription ou un code seul) : la session et le `deviceToken` éventuel sont gardés dans le navigateur ; le jeton d'appareil survit à la déconnexion. Le client va vers `redirect` s'il est un chemin interne (`/…`, jamais `//…` ni une URL), sinon vers `/`.
- R5 — Chaque erreur dit sa vraie cause : « E-mail ou mot de passe incorrect. » (`INVALID_CREDENTIALS`), trop de tentatives (423 `OTP_LOCKED`, 429 `RATE_LIMITED`), serveur injoignable (`NETWORK`), « Code invalide ou expiré. » (`OTP_INVALID`), numéro non confirmé (409 `PHONE_NOT_CONFIRMED`).

## Scénarios

### SPEC-020-10-SC01 — messages d'erreur par cause

Critères : FEAT-020-AC07, FEAT-020-AC06, FEAT-020-AC10

- **Étant donné** les erreurs `INVALID_CREDENTIALS`, `OTP_LOCKED`, `RATE_LIMITED`, `NETWORK`, `OTP_INVALID`, `PHONE_NOT_CONFIRMED`
- **Quand** elles sont traduites
- **Alors** chacune donne son propre message français, sans renvoyer à une autre cause

### SPEC-020-10-SC02 — le jeton d'appareil survit à la déconnexion

Critères : FEAT-020-AC06

- **Étant donné** un navigateur avec une session et un jeton d'appareil gardés
- **Quand** la session locale est effacée (déconnexion)
- **Alors** le jeton d'appareil reste lisible ; un nouveau jeton remplace l'ancien

### SPEC-020-10-SC03 — se connecter et réinitialiser dans un navigateur [evidence: manual]

Critères : FEAT-020-AC06, FEAT-020-AC07, FEAT-020-AC10

- **Étant donné** le site et l'API locaux, avec le faux envoi d'e-mails, et le compte de SPEC-020-07-SC06
- **Quand** il se déconnecte et se reconnecte par mot de passe (appareil mémorisé), se connecte depuis un autre navigateur (code demandé), essaie un mauvais mot de passe, puis réinitialise son mot de passe
- **Alors** chaque étape se comporte comme R1 à R5 ; captures dans `assets/exec-*`

## Erreurs et cas limites

- Stockage bloqué : le jeton d'appareil ne tient pas, un code sera redemandé (comme la session,
  `auth-storage.ts:54-64`).
- Un jeton d'appareil refusé par le serveur n'est pas une erreur : le code est demandé.

## Contrats API et données

Routes de SPEC-020-04 et SPEC-020-05 par `@djafat/sdk`. Clé de stockage _nouvelle_ du jeton
d'appareil, à côté de celles de `auth-storage.ts:10-12`, que `clearSession` n'efface pas.

## Autorisations

Page publique.

## UI et accessibilité

`Input` avec `autocomplete` `email`, `current-password`, `new-password`, `one-time-code` ;
`Checkbox` du kit pour « Se souvenir de cet appareil » ; message d'erreur en `Alert`
(`role="alert"`) ; focus sur le champ du code à l'arrivée sur l'étape du code.

du code, case au nouvel appareil seulement, champs du nouveau mot de passe) : SC03.

## Hypothèses et questions ouvertes

- Technique : le jeton d'appareil est gardé dans `localStorage` comme les jetons de session ; la
  documentation du site prévoyait des cookies `HttpOnly` (docs/07 §7), dette commune à toute la
  session web.

(SC01, SC02). Navigateur réel (SC03), étape `/feature-visual`.
