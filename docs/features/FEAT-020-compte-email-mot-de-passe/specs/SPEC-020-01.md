# SPEC-020-01 — Envoyer les e-mails du compte par le Gmail officiel de DJAFAT

## Comportement observable

Aujourd'hui (`packages/config/src/env.ts:91-99,270-274`), `EMAIL_PROVIDER=smtp` exige
`SMTP_URL` (`smtp://` ou `smtps://user:pass@host:port`) et `EMAIL_FROM`. Un mot de passe
d'application Gmail s'écrit mal dans une URL (espaces, caractères à encoder), et le `.env` local
n'a aucune variable e-mail. Chaque e-mail de code a le même objet, « Votre code de connexion
DJAFAT » (`apps/api/src/modules/auth/providers/email-otp-text.ts:1-21`), quel que soit le but.

Après la spec :

- la configuration accepte aussi `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`
  (_nouveau_), à la place de `SMTP_URL` ;
- chaque e-mail de code dit à quoi il sert (inscription, connexion, nouvel appareil,
  réinitialisation, vérification d'adresse) ;
- deux avis sans code partent par le même SMTP (_nouveau_) : « vous avez déjà un compte » et
  « votre mot de passe a été modifié » ;
- `.env.example` et `.env` ont un bloc Gmail à remplir.

## Règles métier

- R1 — Avec `EMAIL_PROVIDER=smtp`, il faut `SMTP_URL`, ou bien `SMTP_HOST`, `SMTP_USER` et `SMTP_PASSWORD`. Sinon l'API refuse de démarrer et nomme la variable manquante. `SMTP_URL` reste accepté tel quel (rétrocompatible) et gagne s'il est présent. Une variable vide (`SMTP_USER=`) vaut absente, `SMTP_URL` compris (FEAT-020-Q11).
- R2 — `SMTP_PORT` vaut 465 par défaut : TLS dès la connexion sur 465, STARTTLS sur les autres ports (587).
- R3 — Pour `smtp.gmail.com`, les espaces de `SMTP_PASSWORD` sont retirés : Google affiche le mot de passe d'application en quatre groupes de quatre lettres.
- R4 — `EMAIL_FROM` devient facultatif quand `SMTP_USER` est donné : il vaut alors `DJAFAT <SMTP_USER>`. Gmail remplace de toute façon un expéditeur qui n'est pas l'adresse du compte ou un alias vérifié.
- R5 — L'objet et le texte d'un e-mail de code dépendent du but du code : `register`, `login`, `login_device`, `reset_password`, `verify_email`. Le texte contient le code et sa durée de validité ; ni le code ni l'adresse complète ne sont journalisés (adresse masquée `a***@domaine`).
- R6 — Les deux avis passent par un port d'envoi de messages (_nouveau_). En développement (faux envoi), le dernier avis d'une adresse est gardé 10 minutes dans Redis pour les tests et la lecture locale ; en production avec le faux envoi, l'avis est ignoré avec un avertissement, sans faire échouer la requête.
- R7 — `.env.example` documente le bloc Gmail, valeurs vides ; le `.env` local reçoit le même bloc avec `EMAIL_PROVIDER=mock`, à passer à `smtp` une fois `SMTP_USER` et `SMTP_PASSWORD` collés par l'utilisateur. Aucun secret n'entre dans Git.

## Scénarios

### SPEC-020-01-SC01 — configuration Gmail acceptée

Critères : FEAT-020-AC14

- **Étant donné** `EMAIL_PROVIDER=smtp`, `SMTP_HOST=smtp.gmail.com`, `SMTP_USER=djafat@gmail.com`, `SMTP_PASSWORD="abcd efgh ijkl mnop"`, sans `SMTP_PORT` ni `EMAIL_FROM`
- **Quand** la configuration est chargée et les options du transport calculées
- **Alors** elle est acceptée ; le transport vise `smtp.gmail.com:465` en TLS, s'authentifie avec `djafat@gmail.com` / `abcdefghijklmnop`, et l'expéditeur est `DJAFAT <djafat@gmail.com>`

### SPEC-020-01-SC02 — configuration SMTP incomplète refusée

Critères : FEAT-020-AC14

- **Étant donné** `EMAIL_PROVIDER=smtp` et `SMTP_HOST` sans `SMTP_PASSWORD` (puis sans `SMTP_USER`)
- **Quand** la configuration est chargée
- **Alors** elle est refusée et l'erreur nomme `SMTP_PASSWORD` (puis `SMTP_USER`)

### SPEC-020-01-SC03 — `SMTP_URL` inchangé

Critères : FEAT-020-AC14

- **Étant donné** `EMAIL_PROVIDER=smtp`, `SMTP_URL=smtps://u:p@smtp.example.td:465` et `EMAIL_FROM`
- **Quand** les options du transport sont calculées
- **Alors** elles reprennent l'URL, comme avant la spec

### SPEC-020-01-SC04 — un objet par but de code, sans fuite dans les journaux

Critères : FEAT-020-AC14, FEAT-020-AC15

- **Étant donné** un envoi de code `123456` valable 300 s pour chacun des buts `register`, `login`, `login_device`, `reset_password`, `verify_email`
- **Quand** l'e-mail est composé et envoyé par SMTP
- **Alors** chaque objet est propre à son but, le texte contient `123456` et « 5 min », et aucune ligne de journal ne contient le code ni l'adresse complète

### SPEC-020-01-SC05 — avis sans code

Critères : FEAT-020-AC14

- **Étant donné** le faux envoi en développement, puis en production
- **Quand** l'avis « vous avez déjà un compte » et l'avis « mot de passe modifié » sont envoyés à `awa@example.td`
- **Alors** en développement le dernier avis est lisible dans Redis pour `awa@example.td` ; en production il est ignoré sans erreur

### SPEC-020-01-SC06 — un vrai code arrive dans une boîte Gmail [evidence: manual]

Critères : FEAT-020-AC14

- **Étant donné** le `.env` local rempli par l'utilisateur avec l'adresse Gmail de DJAFAT et son mot de passe d'application, et `EMAIL_PROVIDER=smtp`
- **Quand** une inscription est faite avec une adresse de l'utilisateur
- **Alors** le code arrive dans sa boîte de réception (preuve à apporter par l'utilisateur, qui détient le mot de passe)

### SPEC-020-01-SC07 — bloc Gmail dans `.env.example` et `.env`, sans secret [evidence: review]

Critères : FEAT-020-AC14

- **Étant donné** le diff de la branche
- **Quand** `.env.example` est relu, et `.env` (ignoré par Git) ouvert localement
- **Alors** les deux ont `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `EMAIL_FROM` ; `.env.example` n'a aucune valeur secrète

## Erreurs et cas limites

- Échec SMTP pour un code : 503 `OTP_DELIVERY_FAILED`, comme aujourd'hui
  (`smtp-email-otp-delivery.provider.ts:37-50`). Échec SMTP pour un avis : journalisé (code
  d'erreur SMTP, adresse masquée), la requête qui l'envoie réussit quand même.
- Gmail gratuit plafonne l'envoi à environ 500 messages par jour ; au-delà, Gmail refuse
  (`550 5.4.5`) jusqu'au lendemain et les codes répondent 503 `OTP_DELIVERY_FAILED`.

## Contrats API et données

- `@djafat/config` `ApiEnv` : `SMTP_HOST`, `SMTP_PORT` (entier, défaut 465), `SMTP_USER`,
  `SMTP_PASSWORD` (_nouveaux_, facultatifs) ; `EMAIL_FROM` facultatif si `SMTP_USER` est donné.
- `@djafat/types` `OtpDeliveryPort.send` : champ facultatif `purpose` (_nouveau_, rétrocompatible).
- Port d'avis (_nouveau_) dans `auth` : `send({ to, subject, text })`, fournisseurs SMTP et faux
  envoi, choisis par `EMAIL_PROVIDER` comme le port des codes.

## Hypothèses et questions ouvertes

- Technique : un seul module d'options SMTP partagé par les codes et les avis ; texte brut sans
  HTML (meilleure délivrabilité, rien à maintenir).
- Produit : l'adresse Gmail exacte est fournie par l'utilisateur dans `.env` (non bloquant).
- Technique : en production sans SMTP, l'API démarre et les routes e-mail répondent 503
  `EMAIL_UNAVAILABLE` (FEAT-020-Q10) ; le bloc va dans les deux `.env` locaux (FEAT-020-Q12).
