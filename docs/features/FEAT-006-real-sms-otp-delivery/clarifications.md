# FEAT-006 — Clarifications (grill-me)

| ID           | Question                                                                                       | Bloquant | Statut    | Décision (qui, quand)                                                                                                                                                                                                                  | Specs                                                                                |
| ------------ | ---------------------------------------------------------------------------------------------- | -------- | --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| FEAT-006-Q01 | Quel fournisseur SMS réel (agrégateur, Airtel, Tigo) ?                                         | oui      | ouverte   |                                                                                                                                                                                                                                        | hors périmètre — choix commercial ; l'adaptateur générique ne dépend pas de ce choix |
| FEAT-006-Q02 | Contrat HTTP de la passerelle ?                                                                | non      | hypothèse | Générique `POST <SMS_HTTP_URL>` JSON `{ to, from, body }`, avec en option `Authorization: Bearer <SMS_HTTP_API_KEY>`. Compatible avec `infra/mock-sms` et les passerelles locales ; un format différent = un petit adaptateur en plus. | SPEC-006-01                                                                          |
| FEAT-006-Q03 | Texte du SMS ?                                                                                 | non      | hypothèse | `DJAFAT : votre code est 123456. Valable 5 min. Ne le communiquez a personne.` Sans accent (un seul segment GSM-7 sur tous les téléphones), moins de 160 caractères. À relire par le produit.                                          | SPEC-006-01                                                                          |
| FEAT-006-Q04 | Que faire si l'envoi échoue ?                                                                  | non      | hypothèse | Un seul nouvel essai sur erreur réseau ou 5xx (le SMS est cher et un doublon perturbe), puis 503 `OTP_DELIVERY_FAILED`. Aucun nouvel essai sur 4xx (la requête est fausse).                                                            | SPEC-006-01                                                                          |
| FEAT-006-Q05 | Refuser de démarrer en production sans fournisseur réel, plutôt que démarrer en mode dégradé ? | non      | hypothèse | Refuser : une API qui démarre sans pouvoir envoyer de SMS bloque tous les utilisateurs en silence. Une panne visible au déploiement vaut mieux.                                                                                        | SPEC-006-02                                                                          |
| FEAT-006-Q06 | Identifiant d'expéditeur ?                                                                     | non      | hypothèse | `SMS_SENDER_ID`, par défaut `DJAFAT` : 1 à 11 caractères alphanumériques, la limite usuelle des expéditeurs alphanumériques. Son enregistrement auprès des opérateurs se fait côté fournisseur.                                        | SPEC-006-02                                                                          |
