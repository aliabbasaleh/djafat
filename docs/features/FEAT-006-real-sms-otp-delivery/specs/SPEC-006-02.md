# SPEC-006-02 — Choix du fournisseur par configuration, et refus de démarrer en production sans SMS réel

## Comportement observable

Aujourd'hui, `SMS_PROVIDER` (`packages/config/src/env.ts:76`) accepte n'importe
quelle chaîne et n'est lu nulle part. Après :

- `SMS_PROVIDER` vaut `mock` (par défaut) ou `http` ;
- le module d'authentification branche l'adaptateur correspondant ;
- `loadApiEnv` refuse les combinaisons dangereuses.

## Règles métier

- R1 — `NODE_ENV=production` avec `SMS_PROVIDER=mock` est une erreur de configuration : l'API ne démarre pas.
- R2 — `SMS_PROVIDER=http` sans `SMS_HTTP_URL` est une erreur de configuration, quel que soit l'environnement.
- R3 — `SMS_SENDER_ID` vaut par défaut `DJAFAT` et doit contenir 1 à 11 caractères alphanumériques.
- R4 — Toute autre valeur de `SMS_PROVIDER` est refusée.
- R5 — Hors production, sans configuration, le fournisseur reste `mock`.

## Scénarios

### SPEC-006-02-SC01 — production avec mock : refus de démarrer

Critères : FEAT-006-AC04

- **Étant donné** `NODE_ENV=production` et `SMS_PROVIDER=mock`
- **Quand** la configuration est chargée
- **Alors** elle est refusée, avec un message qui explique qu'aucun SMS ne partirait

### SPEC-006-02-SC02 — http sans URL : refus

Critères : FEAT-006-AC04

- **Étant donné** `SMS_PROVIDER=http` sans `SMS_HTTP_URL`, en production comme en test
- **Quand** la configuration est chargée
- **Alors** elle est refusée et l'erreur mentionne `SMS_HTTP_URL`

### SPEC-006-02-SC03 — production avec une passerelle http : accepté

Critères : FEAT-006-AC04

- **Étant donné** `NODE_ENV=production`, `SMS_PROVIDER=http` et `SMS_HTTP_URL=https://sms.example.test/send`
- **Quand** la configuration est chargée
- **Alors** elle est acceptée, avec `SMS_SENDER_ID` à `DJAFAT` par défaut

### SPEC-006-02-SC04 — hors production : mock par défaut, valeurs inconnues refusées

Critères : FEAT-006-AC05

- **Étant donné** `NODE_ENV=test` sans `SMS_PROVIDER`, puis `SMS_PROVIDER=twilio`, puis `SMS_SENDER_ID=DJAFAT-LIVRAISON`
- **Quand** la configuration est chargée
- **Alors** le premier cas donne `mock` ; le deuxième et le troisième (plus de 11 caractères, tiret) sont refusés

### SPEC-006-02-SC05 — le module branche l'adaptateur choisi [evidence: review]

Critères : FEAT-006-AC04, FEAT-006-AC05

- **Étant donné** `SMS_PROVIDER=http`, puis `mock`
- **Quand** l'API démarre
- **Alors** `OTP_DELIVERY_PORT` est respectivement `HttpSmsOtpDeliveryProvider` et `MockOtpDeliveryProvider`. Vérifié en revue et par la démonstration de bout en bout (API réelle et `infra/mock-sms`)

## Erreurs et cas limites

Des valeurs déjà présentes dans un `.env` de dev (`SMS_PROVIDER=mock`) restent valides.

## Contrats API et données

Variables d'environnement : `SMS_PROVIDER` devient `mock | http` ; ajout de
`SMS_HTTP_URL` (URL), `SMS_HTTP_API_KEY` (optionnelle) et `SMS_SENDER_ID`.
