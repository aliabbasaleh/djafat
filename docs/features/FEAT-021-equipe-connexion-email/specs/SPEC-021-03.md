# SPEC-021-03 — Consoles admin et restaurant : connexion par e-mail et mot de passe

## Comportement observable

`/login` de la console admin (`apps/admin/src/app/login/page.tsx`) et de la console restaurant
(`apps/restaurant/src/app/login/page.tsx`) ouvre sur e-mail et mot de passe (maquette
FEAT-021-VIS02) au lieu du numéro de téléphone. Les règles sont celles de SPEC-021-02.

| Console    | Titre                 | Sous-titre (inchangé)                              | Accès                 | Message de refus (inchangé)                             | Après connexion   |
| ---------- | --------------------- | -------------------------------------------------- | --------------------- | ------------------------------------------------------- | ----------------- |
| admin      | « DJAFAT Admin »      | « Connexion réservée au personnel administratif. » | `hasAdminAccess`      | « Ce compte n'a pas accès à l'administration DJAFAT. »  | `/admin`          |
| restaurant | « DJAFAT Restaurant » | « Connexion réservée aux comptes restaurant. »     | `hasRestaurantAccess` | « Ce compte n'est rattaché à aucun restaurant DJAFAT. » | comme aujourd'hui |

## Règles métier

- R1 — États de l'écran : identifiants → (code si appareil inconnu) → connecté ; « Mot de passe
  oublié ? » → e-mail → code et nouveau mot de passe → connecté ; « SMS » (si disponible) → écran
  actuel téléphone puis code.
- R2 — Le bouton principal est désactivé pendant l'envoi ; une erreur s'affiche au-dessus du
  bouton et disparaît dès qu'un champ change.
- R3 — Le jeton d'appareil de la console est gardé dans le navigateur sous `djafat.admin.device`
  ou `djafat.restaurant.device`, et n'est pas effacé à la déconnexion.

## Scénarios

### SPEC-021-03-SC01 — connexion sur un appareil mémorisé

Critères : FEAT-021-AC01, FEAT-021-AC02

- **Étant donné** un administrateur (puis un restaurateur) avec mot de passe, sur un appareil déjà
  mémorisé
- **Quand** il saisit son e-mail et son mot de passe
- **Alors** il arrive sur sa console sans code

### SPEC-021-03-SC02 — appareil inconnu : code par e-mail

Critères : FEAT-021-AC01, FEAT-021-AC02

- **Étant donné** le même compte sur un navigateur neuf
- **Quand** il saisit son e-mail et son mot de passe
- **Alors** l'écran du code montre l'adresse masquée ; le bon code avec « Se souvenir de cet
  appareil » le connecte, et la connexion suivante se fait sans code

### SPEC-021-03-SC03 — mauvais mot de passe

Critères : FEAT-021-AC01, FEAT-021-AC02

- **Étant donné** un e-mail connu et un mauvais mot de passe
- **Quand** il valide
- **Alors** « E-mail ou mot de passe incorrect. » s'affiche et rien n'est gardé

### SPEC-021-03-SC04 — compte sans accès

Critères : FEAT-021-AC01, FEAT-021-AC02

- **Étant donné** un compte client avec mot de passe
- **Quand** il se connecte à la console admin (puis restaurant)
- **Alors** le message de refus de la console s'affiche et rien n'est gardé

### SPEC-021-03-SC05 — mot de passe oublié [evidence: manual]

Critères : FEAT-021-AC04

- **Étant donné** un membre de l'équipe à l'e-mail vérifié
- **Quand** il suit « Mot de passe oublié ? » jusqu'au nouveau mot de passe
- **Alors** il est connecté à la console ; captures d'exécution à l'appui

### SPEC-021-03-SC06 — SMS et WhatsApp grisés tant qu'ils ne sont pas configurés [evidence: manual]

Critères : FEAT-021-AC05

- **Étant donné** le serveur avec le SMS coupé et sans WhatsApp
- **Quand** l'écran de connexion s'affiche
- **Alors** SMS et WhatsApp sont grisés « Bientôt disponible » (capture 1280×800 et 390×844) ; avec
  le SMS disponible, le bouton SMS ouvre l'écran téléphone actuel

## Erreurs et cas limites

Celles de SPEC-021-02 ; une réponse inattendue affiche « Connexion impossible pour le moment. ».

## Contrats API et données

Routes de SPEC-021-02 ; aucune nouvelle.

## Autorisations

Contrôle d'accès inchangé (`hasAdminAccess`, `hasRestaurantAccess`) ; l'API revérifie les rôles.

## UI et accessibilité

- Champs avec libellés visibles (« E-mail », « Mot de passe », « Code à 6 chiffres », « Nouveau
  mot de passe »), `autoComplete` `email`, `current-password`, `one-time-code`, `new-password`.
- Bouton « Afficher » pour le mot de passe ; erreurs dans une zone `role="alert"`.
- Boutons grisés : `disabled` avec la mention « Bientôt disponible » lisible.

## Références visuelles

FEAT-021-VIS02 (attendu, faisant foi) : ordre et présence — titre, e-mail, mot de passe,
« Se connecter », « Mot de passe oublié ? », ligne SMS / WhatsApp. FEAT-021-VIS01 (actuel) :
titres et messages de refus conservés.

## Migrations

N/A — aucune.

## Hypothèses et questions ouvertes

Les deux consoles gardent chacune leur page (déjà deux copies aujourd'hui) : `packages/ui` ne fait
pas d'appel réseau, la logique commune est dans le SDK (FEAT-021-Q06).

## Stratégie de validation

- SC01 à SC04 : logique de connexion de chaque console dans `lib/` avec un faux SDK
  (`apps/admin/src/lib/*.spec.ts`, `apps/restaurant/src/lib/*.spec.ts`).
- SC05, SC06 : captures d'exécution (Chrome sans tête) contre l'API locale.

## Modules existants et points d'intégration

- `apps/admin/src/app/login/page.tsx`, `apps/restaurant/src/app/login/page.tsx` (présentation).
- `apps/admin/src/lib/auth-storage.ts:107`, `apps/restaurant/src/lib/auth-storage.ts:102`
  (logique cliente : accès, session ; ajout du jeton d'appareil).
- `apps/admin/src/lib/api.ts`, `apps/restaurant/src/lib/api.ts` (client `@djafat/sdk`).
