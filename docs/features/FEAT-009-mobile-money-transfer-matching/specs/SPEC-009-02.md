# SPEC-009-02 — Airtel Money et Tigo Cash au numéro marchand

## Comportement observable

`POST /v1/payments { orderId, providerCode: 'airtel_money' | 'tigo_cash', methodCode: 'mobile_money', payerPhone }` → 201, paiement `pending`, `action.instructions` : « Envoyez 12 000 FCFA au +235 60 00 00 10 (DJAFAT) avec Airtel Money, puis indiquez le numéro de transaction reçu par SMS. » La commande reste `awaiting_payment`.

## Règles métier

- R1 — Une seule classe de fournisseur, instanciée par portefeuille configuré dans `MOBILE_MONEY_WALLETS` ; un portefeuille absent n'est pas enregistré, donc ni proposé ni utilisable.
- R2 — Capacités : asynchrone, pas de webhook, pas de remboursement automatique, numéro payeur requis, XAF uniquement.
- R3 — `MOBILE_MONEY_WALLETS` : `code=+235…` séparés par des virgules ; code `[a-z_]+`, numéro E.164 ; invalide → démarrage refusé.
- R4 — Données : `airtel_money` et `tigo_cash` existent dans `payment_providers` (inactifs) avec une configuration N'Djamena désactivée, `fee_bps = 0`. L'activation est une opération de données (admin).

## Scénarios

### SPEC-009-02-SC01 — initiation : instructions avec montant et numéro marchand

Critères : FEAT-009-AC03

- **Étant donné** le portefeuille `airtel_money` au `+23560000010`
- **Quand** un paiement de 12 000 XAF est initié
- **Alors** il est `pending`, sa référence est propre au paiement, et les instructions citent « 12 000 FCFA », « +235 60 00 00 10 » et « Airtel Money »

### SPEC-009-02-SC02 — portefeuilles configurés seulement

Critères : FEAT-009-AC03

- **Étant donné** `MOBILE_MONEY_WALLETS=airtel_money=+23560000010`
- **Quand** les fournisseurs enregistrables sont choisis
- **Alors** `airtel_money` est présent avec ses capacités (asynchrone, sans webhook ni remboursement, numéro payeur requis) et `tigo_cash` absent

### SPEC-009-02-SC03 — configuration invalide refusée

Critères : FEAT-009-AC03

- **Étant donné** `MOBILE_MONEY_WALLETS=airtel_money=60000010` puis `Airtel=+23560000010`
- **Quand** l'environnement est chargé
- **Alors** il est refusé en nommant `MOBILE_MONEY_WALLETS` ; vide ou absent, il est accepté (aucun portefeuille)

## Erreurs et cas limites

Le numéro marchand n'est pas un secret (il est affiché au client).

## Contrats API et données

Variable **nouvelle** `MOBILE_MONEY_WALLETS`. Fournisseur **nouveau** `tigo_cash` dans le seed.
