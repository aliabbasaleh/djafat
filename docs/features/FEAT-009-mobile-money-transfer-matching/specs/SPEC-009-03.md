# SPEC-009-03 — Enregistrer les transferts reçus sur le téléphone marchand

## Comportement observable

- `POST /v1/payments/mobile-money/receipts { providerCode, transactionRef, amount: { minor, currency }, senderPhone, receivedAt }` (staff) → 201 `{ receipt, matchedPaymentId }`. Après l'enregistrement, un rapprochement automatique est tenté (SPEC-009-04).
- `GET /v1/payments/mobile-money/receipts?status=unmatched` (staff) → les transferts non rapprochés, les plus récents d'abord.

## Règles métier

- R1 — Table `mobile_money_receipts` : unicité `(provider_code, transaction_ref)` ; `payment_id` unique ; montant `bigint` > 0 ; statut `unmatched` | `matched` ; source `manual` (réservé : `sms_forwarder`, `api`) ; auteur enregistré.
- R2 — Un numéro de transaction déjà enregistré pour cet opérateur → 409 `RECEIPT_ALREADY_RECORDED`, rien n'est modifié (garanti par la contrainte).
- R3 — Numéro de transaction normalisé (Q08) ; numéro payeur saisi à la tchadienne (FEAT-005) ; opérateur inconnu du registre → 404 `PROVIDER_UNAVAILABLE`.

## Scénarios

### SPEC-009-03-SC01 — enregistrement : normalisé et horodaté, auteur gardé

Critères : FEAT-009-AC04

- **Étant donné** un membre de l'équipe finance
- **Quand** il enregistre `airtel_money`, `ci251107.1432.a81234`, 12 000 XAF, `66 12 34 56`, 14 h 32
- **Alors** le transfert est stocké avec la référence `CI251107.1432.A81234`, le numéro `+23566123456`, le statut `unmatched` et son auteur

### SPEC-009-03-SC02 — doublon refusé

Critères : FEAT-009-AC04, FEAT-009-AC06

- **Étant donné** ce transfert déjà enregistré
- **Quand** la même référence est enregistrée à nouveau pour `airtel_money`
- **Alors** la réponse est 409 `RECEIPT_ALREADY_RECORDED` et une seule ligne existe

### SPEC-009-03-SC03 — garanties de la base [evidence: manual]

Critères : FEAT-009-AC06

- **Étant donné** la migration appliquée sur PostgreSQL
- **Quand** on insère deux fois la même référence, deux transferts pour le même paiement, ou un montant nul
- **Alors** chaque insertion est refusée par une contrainte ; voir `e2e-demo.md`

### SPEC-009-03-SC04 — réservé à l’équipe [evidence: manual]

Critères : FEAT-009-AC04

- **Étant donné** un client connecté
- **Quand** il appelle l'enregistrement ou la liste
- **Alors** il est refusé en 403 ; voir `e2e-demo.md`

## Erreurs et cas limites
