# SPEC-007-01 — Envoi des codes par e-mail (SMTP) et configuration

## Comportement observable

Le port `OtpDeliveryPort` (`@djafat/types`) prévoit déjà le canal `email`, mais
aucun adaptateur n'existe. Après la feature, deux adaptateurs sont branchés sur le
canal e-mail, selon `EMAIL_PROVIDER` :

- `SmtpEmailOtpDelivery` envoie un e-mail par SMTP (`SMTP_URL`) depuis `EMAIL_FROM` ;
- `MockEmailOtpDelivery` stocke le code dans Redis hors production, et lève 503
  `EMAIL_UNAVAILABLE` en production.

## Règles métier

- R1 — Sujet : `Votre code de connexion DJAFAT`. Le texte contient le code, sa durée de validité et une mise en garde contre son partage.
- R2 — Un échec SMTP (connexion, refus du serveur) lève 503 `OTP_DELIVERY_FAILED`, visible tel quel par le client après `AllExceptionsFilter`.
- R3 — Avec `EMAIL_PROVIDER=smtp`, `SMTP_URL` et `EMAIL_FROM` sont obligatoires.
- R4 — `EMAIL_PROVIDER=mock` est autorisé en production : la fonctionnalité y est simplement indisponible, et le démarrage n'est pas bloqué.
- R5 — Jamais l'adresse complète, le code ou le mot de passe SMTP dans les journaux.

## Scénarios

### SPEC-007-01-SC01 — envoi SMTP réel

Critères : FEAT-007-AC05

- **Étant donné** un vrai serveur SMTP local et `EMAIL_FROM=DJAFAT <no-reply@djafat.test>`
- **Quand** le code `482913` est envoyé à `awa@example.td`, valable 600 s
- **Alors** le serveur reçoit un message de `no-reply@djafat.test` pour `awa@example.td`, avec le sujet R1 et un texte contenant `482913` et `10 min`

### SPEC-007-01-SC02 — échec SMTP visible comme OTP_DELIVERY_FAILED

Critères : FEAT-007-AC05

- **Étant donné** un serveur SMTP injoignable
- **Quand** un code est envoyé, et que l'erreur passe par `AllExceptionsFilter`
- **Alors** le client reçoit 503 avec le code `OTP_DELIVERY_FAILED`

### SPEC-007-01-SC03 — mock en production : fonctionnalité indisponible

Critères : FEAT-007-AC05

- **Étant donné** `EMAIL_PROVIDER=mock` en production
- **Quand** un code e-mail est envoyé
- **Alors** l'envoi échoue en 503 `EMAIL_UNAVAILABLE`, et rien n'est écrit dans Redis

### SPEC-007-01-SC04 — configuration

Critères : FEAT-007-AC05

- **Étant donné** `EMAIL_PROVIDER=smtp` sans `SMTP_URL`, ou sans `EMAIL_FROM` ; puis la production avec `EMAIL_PROVIDER` absent
- **Quand** la configuration est chargée
- **Alors** les deux premiers cas sont refusés et nomment la variable manquante ; le troisième est accepté, avec `mock` par défaut

### SPEC-007-01-SC05 — rien de sensible dans les journaux

Critères : FEAT-007-AC06

- **Étant donné** un envoi réussi puis un envoi en échec
- **Quand** on capture les journaux de l'adaptateur
- **Alors** ils ne contiennent ni le code, ni l'adresse complète, ni le mot de passe SMTP

## Erreurs et cas limites

Le délai SMTP est borné (10 s pour la connexion, 15 s au total).

## Contrats API et données

- Variables d'environnement **nouvelles** : `EMAIL_PROVIDER` (`mock` | `smtp`), `SMTP_URL`, `EMAIL_FROM`.
- Codes d'erreur **nouveaux** : `EMAIL_UNAVAILABLE`, `EMAIL_ALREADY_USED`.
