# SPEC-010-01 — Bloquer un livreur qui détient trop d'espèces

## Comportement observable

Après une livraison payée en espèces, si l'argent détenu par le livreur atteint le plafond, il n'est plus proposé pour de nouvelles livraisons ; après un reversement qui le fait repasser sous le plafond, il l'est de nouveau.

## Règles métier

- R1 — Argent détenu = solde débiteur de `CASH_FLOAT:<livreur>` (débits − crédits) dans le grand livre, par devise (lecture seule, `LedgerReadService`).
- R2 — Règle pure `isCashBlocked(détenu, plafond)` : bloqué si `détenu ≥ plafond` ; un plafond ≤ 0 désactive le blocage.
- R3 — Réévaluation par `deliveries` sur `payment.succeeded` (livreur de la livraison de cette commande, s'il y en a un) et sur `courier.cash_remitted` ; `couriers` enregistre l'état (`couriers.cash_blocked_at`).
- R4 — Les deux sélections de candidats (API `findEligibleCandidates`, worker `dispatch.processor`) excluent `cash_blocked_at IS NOT NULL`. Une livraison déjà acceptée n'est jamais retirée (Q04).

## Scénarios

### SPEC-010-01-SC01 — règle de blocage

Critères : FEAT-010-AC02

- **Étant donné** un plafond de 30 000
- **Quand** l'argent détenu vaut 29 999, 30 000, 45 000, puis le plafond 0
- **Alors** le livreur est non bloqué, bloqué, bloqué, puis jamais bloqué

### SPEC-010-01-SC02 — réévaluation après une livraison payée en espèces

Critères : FEAT-010-AC01, FEAT-010-AC02

- **Étant donné** une commande livrée par le livreur L dont le compte `CASH_FLOAT` vaut 31 000 XAF
- **Quand** `payment.succeeded` arrive pour cette commande
- **Alors** le solde est lu dans le grand livre pour L en XAF et L est marqué bloqué ; sans livraison (commande prépayée pas encore répartie), rien n'est fait

### SPEC-010-01-SC03 — déblocage après reversement

Critères : FEAT-010-AC04

- **Étant donné** L bloqué, et un solde redescendu à 1 000 XAF
- **Quand** `courier.cash_remitted` arrive pour L
- **Alors** L est marqué débloqué

### SPEC-010-01-SC04 — les deux répartitions excluent un livreur bloqué

Critères : FEAT-010-AC02

- **Étant donné** la requête de sélection de l'API et celle du worker
- **Quand** elles sont construites
- **Alors** chacune filtre `cash_blocked_at IS NULL`

### SPEC-010-01-SC05 — de bout en bout [evidence: manual]

Critères : FEAT-010-AC02, FEAT-010-AC04

- **Étant donné** l'API, le worker, Postgres et Redis réels, un plafond bas
- **Quand** un livreur livre une commande en espèces qui atteint le plafond, puis qu'une nouvelle commande est prête, puis qu'il reverse
- **Alors** il n'est pas proposé tant qu'il est bloqué, puis l'est de nouveau ; voir `e2e-demo.md`

## Erreurs et cas limites

Si la réévaluation échoue (base indisponible), l'état reste le précédent ; la réévaluation suivante corrige.

## Contrats API et données

Réglage **nouveau** `courier_cash_ceiling_minor` (30 000 par défaut). Colonne **nouvelle** `couriers.cash_blocked_at`. Événement **nouveau** `courier.cash_remitted { courierId }`.
