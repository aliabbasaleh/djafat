# SPEC-023-02 — Le message du client arrive à DJAFAT

## Comportement observable

Meta transmet chaque message reçu sur le numéro de DJAFAT au webhook existant
(`POST /v1/auth/whatsapp/webhook`, `whatsapp-webhook.controller.ts`). Quand le message contient un
code en attente, DJAFAT note **qui** l'a envoyé et ce que cela donne pour l'écran qui a affiché ce
code : un compte à ouvrir, un numéro confirmé sur aucun compte, ou un message venu d'un autre
numéro que celui du compte. DJAFAT ne répond rien sur WhatsApp.

Aujourd'hui, « Code DJAFAT » déclenche une réponse avec un code (`whatsapp-inbound.service.ts:105-133`) :
un message d'entreprise, facturé par Meta depuis le 1er octobre 2026.

## Règles métier

- R1 — Inchangé (SPEC-008-02) : signature `X-Hub-Signature-256` vérifiée (401 sinon, 503 sans
  `WHATSAPP_APP_SECRET`), abonnement par `WHATSAPP_VERIFY_TOKEN`, seuls les messages texte du numéro
  `WHATSAPP_PHONE_NUMBER_ID`, plus vieux de 10 minutes ignorés, un même message (son `id`) traité
  une seule fois ; une requête signée reçoit 200 — sauf une panne du serveur en cours de traitement :
  500, le message n'est pas marqué traité et Meta le redélivre _(v2, 2026-11-28, revue n° 20)_.
- R2 — Inchangé (FEAT-017) : un message de commande (`DJF1 …`) va aux commandes sans Internet.
- R3 — Un message de code contient « DJAFAT » (majuscules et accents ignorés) et un seul nombre de
  6 chiffres qui ne touche pas d'autres chiffres. Tout autre message est ignoré, « Code DJAFAT »
  compris.
- R4 — L'expéditeur est `+<from>`, lu comme tout numéro (FEAT-005, FEAT-024) : un numéro tchadien
  ou étranger valable ; sinon le message est ignoré.
- R5 — Un expéditeur verrouillé est ignoré. Le verrou est le **sien, propre à WhatsApp**
  (`auth_target_locks` sous la clé `whatsapp:<numéro>`, mêmes seuils que les codes) : seuls des
  messages vraiment envoyés de ce numéro — Meta signe l'expéditeur — peuvent l'enclencher ; de
  mauvais codes SMS tapés par un tiers sur `POST /auth/otp/verify` ne bloquent pas WhatsApp. Un
  code qui n'attend aucun message (inconnu, expiré, déjà reçu d'un autre numéro) compte comme un
  échec sur ce verrou (`registerFailedAttempt`) et est journalisé (`AUTH_OTP_FAILED`, canal
  `whatsapp`). _(v2, 2026-11-28, revue n° 1)_
- R6 — Un code en attente est pris une seule fois (le premier message gagne), avec l'expéditeur et
  l'issue. _(v2, 2026-11-28, revue n° 2 : le même message du même expéditeur, redélivré par Meta après un
  premier traitement interrompu, rend la même issue et en termine l'effet — numéro confirmé —, sans
  compter d'échec.)_ Les issues :
  - **connexion** — le compte (non supprimé) de ce numéro s'ouvre si son numéro est confirmé, ou
    s'il n'a ni e-mail vérifié ni mot de passe : la règle d'un code SMS (SPEC-020-06 R4). Sinon —
    aucun compte, ou un compte créé par e-mail au numéro non confirmé — l'issue est « numéro
    confirmé sur aucun compte », sans dire lequel des deux cas. Un message ne crée jamais de
    compte ;
  - **nouvel appareil** — l'expéditeur doit être le numéro confirmé du compte ; sinon « autre
    numéro » ;
  - **confirmation** — l'expéditeur doit être le numéro du compte : le numéro est confirmé tout de
    suite (`phone_verified_at`, journal `AUTH_PHONE_VERIFIED` canal `whatsapp`) ; sinon « autre
    numéro ».
- R7 — Une issue « compte à ouvrir » ou « numéro confirmé » efface les échecs de l'expéditeur
  (`clearLock`) et est journalisée (`AUTH_OTP_VERIFIED`, canal `whatsapp`). « Autre numéro » ne
  compte pas comme un échec.
- R8 — DJAFAT n'envoie aucun message WhatsApp en réponse, quelle que soit l'issue : ni code, ni
  confirmation, ni erreur.

## Scénarios

### SPEC-023-02-SC01 — connexion : le compte au numéro confirmé est retenu pour l'écran

Critères : FEAT-023-AC02, FEAT-023-AC04

- **Étant donné** un code de connexion en attente et un compte au numéro `+23566123456` confirmé
- **Quand** arrive, signé, « Je me connecte à DJAFAT : <code> (n'envoyez ce code…) » depuis
  `23566123456`
- **Alors** le code est pris avec l'expéditeur `+23566123456` et l'issue « compte à ouvrir » pour
  ce compte ; aucun message n'est envoyé par WhatsApp ; Meta reçoit 200.

### SPEC-023-02-SC02 — connexion : numéro étranger confirmé

Critères : FEAT-023-AC02

- **Étant donné** un compte au numéro `+33612345678`, confirmé
- **Quand** son message de code arrive depuis `33612345678`
- **Alors** l'issue est « compte à ouvrir » pour ce compte.

### SPEC-023-02-SC03 — connexion : numéro confirmé sur aucun compte

Critères : FEAT-023-AC03

- **Étant donné** un code de connexion en attente
- **Quand** il arrive depuis un numéro sans compte, ou depuis le numéro non confirmé d'un compte
  créé par e-mail
- **Alors** l'issue est « numéro confirmé sur aucun compte », avec l'expéditeur ; aucun compte
  n'est créé ni ouvert ; les deux cas sont identiques.

### SPEC-023-02-SC04 — code inconnu ou expiré : échec compté, puis expéditeur verrouillé

Critères : FEAT-023-AC02

- **Étant donné** un expéditeur qui envoie des codes que personne n'attend
- **Quand** il atteint le seuil d'échecs
- **Alors** chaque message compte un échec sur son verrou WhatsApp ; une fois verrouillé, même un
  bon code de sa part est ignoré jusqu'à la fin du verrou.

### SPEC-023-02-SC05 — un code n'est pris qu'une fois

Critères : FEAT-023-AC02

- **Étant donné** un code de connexion déjà pris par un premier message
- **Quand** un second message (autre `id`, autre expéditeur) porte le même code
- **Alors** le second ne change rien (et compte comme un échec pour son expéditeur) ; le même
  message livré deux fois par Meta (même `id`) n'est traité qu'une fois, sans échec compté.

### SPEC-023-02-SC06 — messages ignorés

Critères : FEAT-023-AC04

- **Étant donné** des codes en attente
- **Quand** arrivent « Code DJAFAT », un message sans « DJAFAT », un message avec deux nombres de
  6 chiffres, un numéro invalide, un message de plus de 10 minutes, une photo, ou un message pour
  un autre numéro d'entreprise
- **Alors** aucun code n'est pris, aucun échec n'est compté et rien n'est envoyé.

### SPEC-023-02-SC07 — confirmation et nouvel appareil : le message doit venir du numéro du compte

Critères : FEAT-023-AC02

- **Étant donné** un code de confirmation pour un compte au numéro `+33612345678`, et un code de
  nouvel appareil pour un compte au numéro confirmé `+23566123456`
- **Quand** chacun arrive d'abord depuis un autre numéro
- **Alors** l'issue est « autre numéro », aucun échec n'est compté et le numéro du compte n'est pas
  confirmé ; envoyé depuis le bon numéro (avec un nouveau code), la confirmation marque le numéro
  confirmé dès l'arrivée et le nouvel appareil a l'issue « compte à ouvrir ».

### SPEC-023-02-SC08 — un numéro verrouillé par des codes SMS se connecte quand même par WhatsApp

Critères : FEAT-023-AC02

- **Étant donné** un compte au numéro `+23566123456` confirmé, et dix mauvais codes SMS tapés pour
  ce numéro par un tiers (`POST /auth/otp/verify`) : le numéro est verrouillé pour les codes SMS
- **Quand** le client envoie de ce numéro le code affiché par son écran
- **Alors** l'issue est « compte à ouvrir » _(v2, 2026-11-28, revue n° 1)_

### SPEC-023-02-SC09 — le même message redélivré termine la confirmation, sans échec

Critères : FEAT-023-AC05

- **Étant donné** un code de confirmation, et un premier traitement du message interrompu après la
  prise du code (panne de la base)
- **Quand** Meta redélivre le même message du même numéro
- **Alors** l'issue est « compte à ouvrir », le numéro devient confirmé, et aucun échec n'est compté
  _(v2, 2026-11-28, revue n° 2)_

### SPEC-023-02-SC10 — un message de commande n'est jamais lu comme un code

Critères : FEAT-023-AC04

- **Étant donné** un message de commande sans Internet (`DJF1 …`, FEAT-017) qui contient aussi
  « DJAFAT » et un montant de 6 chiffres
- **Quand** il arrive, signé
- **Alors** il part aux commandes (une seule fois) et aucun code n'est pris ni compté
  _(v2, 2026-11-28, revue n° 8)_

## Erreurs et cas limites

- Requête non signée : 401, rien n'est lu (R1). Corps illisible mais signé : 200, rien.
- Deux messages identiques de Meta (même `id`) : un seul est traité (R1).
- Un message qui arrive après l'expiration du code : échec compté (R5), l'écran dit « expiré »
  (SPEC-023-03).
- Base indisponible pendant le traitement : l'erreur est journalisée ; Meta redélivrera (500).

## Contrats API et données

Route existante `POST /v1/auth/whatsapp/webhook` (inchangée pour Meta). Table `whatsapp_codes`
(SPEC-023-01) : `received_at`, `sender_phone`, `outcome` (`matched` | `not_confirmed` |
`wrong_number`), `matched_user_id`. Aucune nouvelle variable d'environnement.

## Autorisations

De Meta à DJAFAT, jamais un utilisateur : pas de `@RequireAuth()`, l'authenticité est la signature
HMAC du corps brut (FEAT-008).

## Hypothèses et questions ouvertes

- Forme du message reconnu : « DJAFAT » et un seul nombre de 6 chiffres (FEAT-023-Q07).
- Comptes ouverts : ceux qu'ouvre un code SMS, jamais de création (FEAT-023-Q08).
- Un code inconnu compte comme un échec, « autre numéro » non (FEAT-023-Q09).
