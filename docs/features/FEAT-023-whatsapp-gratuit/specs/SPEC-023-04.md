# SPEC-023-04 — L'e-mail « Nouvelle connexion par WhatsApp »

## Comportement observable

Après chaque connexion ouverte par un message WhatsApp (connexion par code, code d'un nouvel
appareil), le compte reçoit un e-mail gratuit qui dit quand et sur quel appareil. S'il n'était pas
à l'origine de la connexion — quelqu'un lui a fait envoyer un code (hameçonnage, FEAT-023-Q03) —
l'e-mail dit quoi faire.

Aujourd'hui, une connexion n'envoie aucun e-mail ; les avis sans code existent
(`account-notice.port.ts`, texte `providers/account-notice-text.ts`, envoi `smtp` ou faux selon
`EMAIL_PROVIDER`).

## Règles métier

- R1 — Envoyé après chaque session ouverte par WhatsApp (SPEC-023-03 R4, R5), et seulement
  alors : ni pour une confirmation de numéro, ni pour les autres moyens de connexion.
- R2 — À l'adresse e-mail vérifiée du compte. Sans adresse vérifiée, rien n'est envoyé ; la
  connexion s'ouvre quand même.
- R3 — Objet « Nouvelle connexion par WhatsApp ». Le texte donne la date et l'heure de N'Djamena,
  l'appareil lu dans la demande de l'écran connecté (navigateur et système : « Chrome sur
  Android », « Safari sur iPhone », « l'application DJAFAT sur Android »… ; inconnu : « un appareil
  non reconnu »), puis : rien à faire si c'est vous ; sinon, quelqu'un vous a sans doute demandé
  d'envoyer un code — ne le faites jamais pour une autre personne — et « Mot de passe oublié ? »
  sur la page « Compte » donne un nouveau mot de passe et déconnecte tous les appareils ; puis
  contactez DJAFAT.
- R4 — Aucun code, aucun lien qui connecte, aucune adresse IP dans l'e-mail.
- R5 — Au mieux, comme les autres avis : un e-mail qui ne part pas ne défait pas la connexion et
  n'est pas une erreur pour l'écran (`AccountNoticePort`, `NoticeOutcome`).

## Scénarios

### SPEC-023-04-SC01 — connexion par WhatsApp : l'e-mail part, avec l'appareil

Critères : FEAT-023-AC09

- **Étant donné** un compte à l'adresse vérifiée `awa@example.com`
- **Quand** une session s'ouvre par WhatsApp depuis Chrome sur Android, le 25 novembre 2026 à
  14 h 05 UTC
- **Alors** un e-mail « Nouvelle connexion par WhatsApp » part à `awa@example.com`, qui dit « 25
  novembre 2026 à 15:05 » (heure de N'Djamena) et « Chrome sur Android », et dit quoi faire si ce
  n'est pas vous ; il ne contient ni code, ni lien de connexion, ni adresse IP.

### SPEC-023-04-SC02 — sans adresse vérifiée : pas d'e-mail, connexion ouverte

Critères : FEAT-023-AC09

- **Étant donné** un compte créé par SMS, sans adresse e-mail vérifiée
- **Quand** une session s'ouvre par WhatsApp
- **Alors** aucun e-mail ne part et la session est rendue à l'écran.

### SPEC-023-04-SC03 — l'e-mail ne part pas : la connexion reste

Critères : FEAT-023-AC09

- **Étant donné** le serveur d'e-mail qui refuse
- **Quand** une session s'ouvre par WhatsApp
- **Alors** la session est rendue ; l'échec est journalisé sans l'adresse.

### SPEC-023-04-SC04 — l'appareil en mots

Critères : FEAT-023-AC09

- **Étant donné** les en-têtes `User-Agent` de Chrome sur Android, Safari sur iPhone, Firefox sur
  Windows, Edge sur Windows, Safari sur Mac, d'une application DJAFAT sur Android (`okhttp/4.12.0`)
  et une valeur absente
- **Quand** l'e-mail les décrit
- **Alors** « Chrome sur Android », « Safari sur iPhone », « Firefox sur Windows », « Edge sur
  Windows », « Safari sur Mac », « l'application DJAFAT sur Android », « un appareil non reconnu ».

### SPEC-023-04-SC05 — les autres connexions n'envoient rien

Critères : FEAT-023-AC09

- **Étant donné** un compte à l'adresse vérifiée
- **Quand** il se connecte par mot de passe, par code e-mail, ou confirme son numéro par WhatsApp
- **Alors** aucun e-mail « Nouvelle connexion par WhatsApp ».

## Erreurs et cas limites

R5 : jamais d'erreur rendue pour l'e-mail. Un en-tête `User-Agent` très long ou bizarre :
« un appareil non reconnu ».

## Contrats API et données

- _nouveau_ avis `{ kind: 'whatsapp_login', to, at, device }` de `AccountNotice`
  (`account-notice.port.ts`) ; son texte dans `account-notice-text.ts` ; les fournisseurs `smtp` et
  faux existants l'envoient tels quels.
- Aucune donnée nouvelle.

## Hypothèses et questions ouvertes

- Sans adresse vérifiée, la connexion s'ouvre sans e-mail : la refuser fermerait les comptes créés
  par SMS ou par téléphone, alors que le SMS est coupé en production (FEAT-023-Q12).
- L'appareil se lit dans `User-Agent` ; seules les applications de DJAFAT appellent l'API sans
  navigateur (Android : `okhttp`, iPhone : `CFNetwork`), d'où « l'application DJAFAT »
  (FEAT-023-Q13).

## Stratégie de validation

- SC01, SC02, SC03, SC05 : service (`whatsapp-code.service.spec.ts`) avec un faux
  `AccountNoticePort` ; texte : `account-notice.provider.spec.ts`.
- SC04 : fonction pure (`device-label.spec.ts`).
- Intégration réelle : l'e-mail de SC01 lu dans la boîte du faux fournisseur
  (`whatsapp-login.int.spec.ts`).
