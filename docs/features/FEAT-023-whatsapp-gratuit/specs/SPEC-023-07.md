# SPEC-023-07 — WhatsApp dans la connexion des applications d'équipe

## Comportement observable

La console admin, la console restaurant et l'application livreur proposent « ou recevoir un code
par téléphone » : SMS puis WhatsApp, chacun seulement si le serveur l'offre (FEAT-021, SPEC-021-02
R5). WhatsApp y suit le même parcours que sur le site : le code à envoyer, l'attente, la connexion
toute seule — puis le contrôle du rôle de l'application, comme pour toute connexion d'équipe.

Aujourd'hui : numéro et code reçu en réponse à « Code DJAFAT »
(`apps/admin/src/app/login/page.tsx:223-262`, `:542-600` ; `apps/restaurant/src/app/login/page.tsx:223-264`,
`:550-610` ; `apps/courier/app/(auth)/login.tsx:202-241`, `:507-520`), par `teamVerifyPhoneCode`
(`packages/sdk/src/team-login.ts:165-178`).

## Règles métier

- R1 — « WhatsApp » affiche la vue WhatsApp de SPEC-023-05 R1 (mêmes textes, même ordre), sans
  champ de numéro, et attend comme SPEC-023-05 R2.
- R2 — Connecté : la session passe par le contrôle du rôle de l'application
  (`acceptTeamSignIn`, SPEC-021-02 R3) : gardée si le compte a le rôle, sinon le message de refus
  de l'application, et rien n'est gardé ; l'écran quitte alors la vue WhatsApp (code consommé)
  pour le formulaire, où le refus s'affiche _(v2, 2026-11-28, revue n° 5)_.
- R3 — Numéro confirmé sur aucun compte : « Ce numéro n'est confirmé sur aucun compte » avec
  « Se connecter par e-mail » (retour au formulaire e-mail et mot de passe). Pas de « Créer un
  compte » : un compte d'équipe ne se crée pas depuis ces écrans ; le lien « Pas encore de compte ? »
  existant (console restaurant, application livreur) reste sur le formulaire.
- R4 — Expiré : « Ce code a expiré. » avec « Nouveau code ».
- R5 — Le code par SMS ne change pas ; WhatsApp éteint : « Bientôt disponible » (SPEC-021-02 R5).
- R6 — Application livreur : « Ouvrir WhatsApp » ouvre WhatsApp (`Linking`), l'attente reprend au
  retour (SPEC-023-05 R8).

## Scénarios

### SPEC-023-07-SC01 — compte avec le rôle : connecté

Critères : FEAT-023-AC02

- **Étant donné** la console restaurant et la réponse « connecté » pour un responsable de
  restaurant
- **Quand** l'attente reçoit la session
- **Alors** la session est gardée (et le jeton d'appareil s'il y en a un) ; la console s'ouvre.

### SPEC-023-07-SC02 — compte sans le rôle : refusé, rien n'est gardé

Critères : FEAT-023-AC02

- **Étant donné** la console admin et la réponse « connecté » pour un compte client
- **Quand** l'attente reçoit la session
- **Alors** le message de refus de la console ; aucune session n'est gardée.

### SPEC-023-07-SC03 — numéro confirmé sur aucun compte : « Se connecter par e-mail »

Critères : FEAT-023-AC03

- **Étant donné** la réponse « numéro confirmé sur aucun compte »
- **Quand** l'application d'équipe l'affiche
- **Alors** « Ce numéro n'est confirmé sur aucun compte » et « Se connecter par e-mail », sans
  « Créer un compte ».

### SPEC-023-07-SC04 — la vue WhatsApp de l'équipe

Critères : FEAT-023-AC01

- **Étant donné** WhatsApp en service
- **Quand** on choisit WhatsApp dans « ou recevoir un code par téléphone »
- **Alors** la vue de SPEC-023-05 R1, sans champ de numéro ; « ← Autre moyen de connexion » revient
  au formulaire.

### SPEC-023-07-SC05 — les écrans réels [evidence: manual]

Critères : FEAT-023-AC01, FEAT-023-AC02

- **Étant donné** l'API et les trois applications d'équipe sur un poste, un message simulé
- **Quand** un responsable se connecte par WhatsApp à la console restaurant (1280×800), et un
  livreur à l'application livreur (version web, 390×844)
- **Alors** les captures `exec-SPEC-023-07-*` montrent la vue WhatsApp et la console ouverte.

## Erreurs et cas limites

Ceux de SPEC-023-05. Une session refusée pour le rôle n'est jamais gardée (R2).

## Contrats API et données

Les routes de SPEC-023-01 et SPEC-023-03. SDK : _nouveau_ `teamWhatsappSignIn` (la session de
l'attente → `acceptTeamSignIn`) ; `TeamAuthCalls.verifyPhoneLoginCode` ne garde que le SMS.

## Autorisations

Le contrôle du rôle de chaque application (SPEC-021-02 R3), inchangé.

## UI et accessibilité

en 390×844).
