# SPEC-022-02 — S'inscrire comme livreur

## Comportement observable

Aujourd'hui un livreur n'existe que si l'équipe lui donne le rôle `courier` et une ligne `couriers`
(`apps/api/prisma/schema.prisma:850` : `vehicle_type` en texte libre, ni quartier, ni dossier). Après :
le formulaire livreur (FEAT-022-VIS02) crée le compte par le parcours de FEAT-020 (code par e-mail),
et le compte confirmé est un livreur dont le dossier est « à compléter » : il ne reçoit aucune course.

## Règles métier

- R1 — Champs : ceux du client de FEAT-020 (nom complet, téléphone, e-mail, mot de passe et
  confirmation), plus le véhicule (Moto, Vélo, Voiture, À pied), le quartier où il travaille
  d'habitude (liste de SPEC-022-09, ou « Autre » avec le nom saisi), la date de naissance, et la case
  obligatoire « J'accepte les conditions d'utilisation » (lien vers la page « Conditions »).
- R2 — Âge (FEAT-022-Q04) : au moins 18 ans le jour de l'inscription (heure de N'Djamena) ; sinon
  « Il faut avoir au moins 18 ans pour livrer avec DJAFAT. » et rien n'est envoyé.
- R3 — Le code par e-mail, son renvoi, ses limites et la création du compte suivent FEAT-020
  (SPEC-020-01). Rien n'existe avant le bon code.
- R4 — Le bon code crée, dans la même transaction : le compte, le rôle `courier`, la ligne `couriers`
  (véhicule, quartier) et le dossier livreur à l'état `to_complete`, avec la date d'acceptation des
  conditions (FEAT-022-Q05). La session s'ouvre comme pour un client.
- R5 — Tant que le dossier n'est pas validé (SPEC-022-07), le livreur ne peut pas passer « En
  ligne » et ne reçoit aucune course (SPEC-022-06 R5).
- R6 — Après le code : « ✅ Compte livreur créé », la liste de ce qu'il faudra compléter dans
  l'application livreur, et « Ouvrir l'application livreur ».
- R7 — Un e-mail ou un téléphone déjà utilisé : même réponse qu'aujourd'hui (FEAT-020 : un numéro
  déjà pris est dit ouvertement, 409 `PHONE_ALREADY_USED`, décision FEAT-020-Q06 ; une adresse déjà
  prise ne se distingue pas d'une adresse libre) ; jamais un second compte (SPEC-022-08 pour ajouter
  le rôle à son compte). _(v2)_

## Scénarios

### SPEC-022-02-SC01 — inscription complète : un livreur « à compléter »

Critères : FEAT-022-AC03

- **Étant donné** un visiteur de 25 ans, avec un e-mail et un téléphone inconnus
- **Quand** il remplit le formulaire livreur (Moto, quartier Moursal, conditions cochées) puis saisit
  le bon code
- **Alors** le compte existe avec les rôles `customer` et `courier`, une ligne `couriers` (véhicule
  `moto`, quartier Moursal), un dossier `to_complete` avec la date d'acceptation, et une session

### SPEC-022-02-SC02 — moins de 18 ans : refusé avant l'envoi

Critères : FEAT-022-AC03

- **Étant donné** une date de naissance qui donne 17 ans et 364 jours ; puis 18 ans pile
- **Quand** il envoie le formulaire
- **Alors** la première est refusée avec « Il faut avoir au moins 18 ans pour livrer avec DJAFAT. »
  (côté écran et, si elle arrive quand même, côté API : 422 `UNDERAGE`) ; la seconde passe

### SPEC-022-02-SC03 — champs obligatoires

Critères : FEAT-022-AC03

- **Étant donné** le formulaire livreur
- **Quand** il l'envoie sans véhicule, sans quartier, avec « Autre » vide, ou sans cocher les
  conditions
- **Alors** chaque champ manquant affiche son message et rien n'est envoyé ; l'API refuse aussi (422,
  champs en erreur)

### SPEC-022-02-SC04 — aucune course avant la validation

Critères : FEAT-022-AC03

- **Étant donné** le livreur de SC01, dossier `to_complete`
- **Quand** il demande à passer « En ligne » (`POST /couriers/me/status`, _v3 : la route existante_)
- **Alors** 409 `COURIER_NOT_APPROVED` et son statut reste `offline` ; la répartition des courses ne
  le choisit jamais

### SPEC-022-02-SC05 — rien n'existe avant le bon code

Critères : FEAT-022-AC03

- **Étant donné** un formulaire livreur envoyé
- **Quand** le code n'est pas saisi, ou est faux
- **Alors** aucun compte, aucun rôle, aucune ligne `couriers` ni dossier n'existe

### SPEC-022-02-SC06 — message de fin [evidence: manual]

Critères : FEAT-022-AC03

- **Étant donné** le bon code saisi
- **Quand** l'écran suivant s'affiche
- **Alors** « ✅ Compte livreur créé », la liste à compléter et « Ouvrir l'application livreur »
  (FEAT-022-VIS02)

## Erreurs et cas limites

422 `UNDERAGE`, 422 pour un champ manquant ; les erreurs de FEAT-020 pour le reste (e-mail, code,
limites). Une date de naissance dans le futur ou avant 1900 : « Date de naissance invalide. ». Un
quartier « Autre » de plus de 60 caractères : refusé.

## Contrats API et données

`POST /auth/register` accepte, en plus des champs de FEAT-020 (_nouveau_, facultatif, `.strict()`) :
`accountType: 'customer' | 'courier' | 'restaurant'` (défaut `customer`), et pour `courier` :
`vehicle: 'moto' | 'velo' | 'voiture' | 'a_pied'`, `neighbourhoodId` (uuid) **ou**
`neighbourhoodOther` (texte, 2 à 60), `birthDate` (`YYYY-MM-DD`), `acceptTerms: true`. Ces données
attendent avec l'inscription en attente (FEAT-020) jusqu'au bon code. Données (_nouveau_, migration) :
`couriers.vehicle_type` limité aux quatre valeurs, `couriers.neighbourhood_id` / `neighbourhood_other`,
`couriers.birth_date` ; table `courier_applications` (état `to_complete | pending_review | approved |
rejected`, motif de refus, dates d'acceptation des conditions, d'envoi et de décision, décideur). La
création passe par un port (`common/ports`, _nouveau_ `COURIER_ONBOARDING_PORT`) que fournit le module
`couriers` : `auth` n'atteint que `users` (graphe des modules).

## Autorisations

Public jusqu'au code ; ensuite la session du nouveau compte.

## UI et accessibilité

Véhicule : quatre boutons radio (un groupe nommé « Véhicule ») ; quartier : liste déroulante avec
« Autre » qui fait apparaître un champ texte ; date de naissance : champ date avec le format
attendu ; chaque erreur s'affiche sous son champ et est annoncée (rôle `alert`).

## Références visuelles

## Migrations

Ajout de colonnes nullables à `couriers` et création de `courier_applications` ; les livreurs
existants reçoivent un dossier `approved` (ils travaillent déjà), daté de la migration. Retour en
arrière : supprimer la table et les colonnes (aucune donnée existante n'en dépend).

## Hypothèses et questions ouvertes

Le refus « moins de 18 ans » se fait sur la date déclarée ; l'administrateur la compare à la pièce
d'identité (SPEC-022-07).
