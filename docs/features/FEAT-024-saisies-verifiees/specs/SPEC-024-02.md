# SPEC-024-02 — Numéros dans les formulaires

## Comportement observable

Aujourd'hui, chaque champ de numéro est une case vide (FEAT-024-VIS01). Le serveur accepte tout
numéro au format international (`makePhoneInputSchema`, `packages/validation/src/common.schema.ts:58`,
FEAT-005), y compris un fixe à l'inscription ou pour le Mobile Money du livreur. Après :

- chaque champ montre « +235 » devant la case ;
- un numéro étranger reste accepté pour un compte et pour les numéros à appeler ;
- un fixe est refusé comme numéro d'un compte ;
- le Mobile Money n'accepte qu'un portable du Tchad.

## Règles métier

- R1 — Champ : « +235 » s'affiche devant la case, et taper les 8 chiffres suffit (« 66 12 34 56 »).
  Dès que la saisie commence par « + » ou « 00 », le numéro porte son propre indicatif : « +235 »
  ne s'affiche plus. Les champs concernés sont ceux des cinq applications listés au point « UI et
  accessibilité ».
- R2 — Numéro d'un compte (inscription client, livreur, restaurant) : un portable du Tchad ou un
  numéro étranger. Un fixe du Tchad est refusé avec « Ce numéro est un fixe : indiquez un numéro de
  portable (ex. 66 12 34 56). »
- R3 — Numéros à appeler (contact d'urgence, destinataire d'une adresse, téléphone du restaurant,
  commande par téléphone) : tout numéro valide, étranger ou fixe compris (FEAT-005 inchangé).
- R4 — Mobile Money : seulement un portable du Tchad (FEAT-024-Q07).
  - Un numéro étranger affiche « Le numéro Mobile Money est un numéro du Tchad : il commence par
    +235 (ex. 66 12 34 56). »
  - Un fixe affiche le message de R2.
  - Le champ garde « +235 » devant la case, même si la saisie commence par « + ».
- R5 — Le serveur refait R2 et R4 : 422 `VALIDATION_ERROR` sur le champ (`phone`,
  `mobileMoney.number`), avec le même message, et rien n'est créé ni enregistré.
- R6 — Mise en forme inchangée (FEAT-005) : espaces, tirets, « 00 », chiffres arabes ; le numéro
  gardé est toujours au format international (`+235…`, `+33…`).

## Scénarios

### SPEC-024-02-SC01 — inscription avec un numéro étranger

Critères : FEAT-024-AC01

- **Étant donné** un visiteur avec un e-mail et le numéro `+33 6 12 34 56 78`
- **Quand** il envoie le formulaire client puis saisit le code reçu par e-mail
- **Alors** le compte existe avec `+33612345678` ; il se connecte par e-mail et mot de passe

### SPEC-024-02-SC02 — inscription avec un fixe : refusée

Critères : FEAT-024-AC03, FEAT-024-AC08

- **Étant donné** le formulaire d'inscription (client, livreur ou restaurant)
- **Quand** il tape `22 51 23 45` ; puis la même requête arrive directement à `POST /auth/register`
- **Alors** l'écran affiche le message de R2 sous le champ sans rien envoyer ; le serveur répond
  422 `VALIDATION_ERROR` sur `phone` avec le même message, et aucune inscription en attente ni
  e-mail n'existe

### SPEC-024-02-SC03 — numéros à appeler : étranger et fixe acceptés

Critères : FEAT-024-AC01, FEAT-024-AC03

- **Étant donné** le dossier d'un livreur
- **Quand** il enregistre un contact d'urgence au `+33 6 12 34 56 78`, puis au `22 51 23 45`
- **Alors** les deux sont gardés (`+33612345678`, `+23522512345`)

### SPEC-024-02-SC04 — Mobile Money : portable du Tchad seulement

Critères : FEAT-024-AC04, FEAT-024-AC08

- **Étant donné** le dossier d'un livreur
- **Quand** il enregistre le Mobile Money `+33 6 12 34 56 78`, puis `22 51 23 45`, puis `66 12 34 56`
- **Alors** le premier est refusé avec le message de R4, le deuxième avec celui de R2 (écran, puis
  API : 422 sur `mobileMoney.number`), le troisième est gardé (`+23566123456`)

### SPEC-024-02-SC05 — « +235 » devant la case

Critères : FEAT-024-AC05

- **Étant donné** un champ de numéro
- **Quand** il est vide, puis contient « 66 12 », puis « +33 6 »
- **Alors** « +235 » s'affiche devant la case les deux premières fois, plus la troisième ; pour le
  Mobile Money, il reste affiché

## Erreurs et cas limites

- Un numéro mal formé garde le message de FEAT-005, reformulé : « Numéro invalide : 8 chiffres
  (ex. 66 12 34 56), ou l'indicatif d'un autre pays (+33…). »
- Un numéro du Tchad qui n'a pas 8 chiffres : invalide (FEAT-005).
- Un compte existant avec un fixe ou un numéro étranger n'est pas modifié (FEAT-024-Q09).

## Contrats API et données

- Les routes ne changent pas.
- `makePhoneInputSchema(market, use)` (_nouveau_ second paramètre) :
  - `account` refuse le fixe ;
  - `mobile_money` refuse l'étranger et le fixe ;
  - `contact` (défaut) garde le comportement de FEAT-005.
- `LAUNCH_MARKET.fixedLinePrefixes` (_nouveau_).
- Domaine : `phoneKind(e164, market)` → `mobile | fixed | foreign` (_nouveau_,
  `packages/core/src/phone/`).
- Le marché vu par les écrans : `LAUNCH_PHONE_MARKET` (_nouveau_, `@djafat/core`), identique à
  `LAUNCH_MARKET` (un test le vérifie).
- Les reçus Mobile Money (FEAT-016) gardent `contact` (FEAT-024-Q08).

## UI et accessibilité

« +235 » est un texte affiché devant la case, lié au champ (le nom accessible du champ dit
« Numéro de téléphone, indicatif +235 ») ; il n'est pas saisissable.

Champs concernés :

- site : inscription, connexion par SMS, adresses ;
- application client : inscription, connexion, adresses ;
- application livreur : connexion, Mobile Money, contact d'urgence ;
- console admin : connexion, commande par téléphone ;
- console restaurant : connexion ;
- formulaires livreur et restaurant de FEAT-022.
