# SPEC-024-01 — SMS : portables du Tchad seulement

## Comportement observable

Aujourd'hui, tout numéro au format international reçoit un code par SMS quand le SMS est en service
(`OtpService.requestCode`, `apps/api/src/modules/auth/otp.service.ts:124`). Seul l'arrêt du SMS
est vérifié (`SMS_PROVIDER=disabled` → 503 `SMS_UNAVAILABLE`, ligne 131). Après : un numéro étranger
ou un fixe du Tchad ne reçoit jamais de SMS. L'écran l'arrête avant l'envoi, et le serveur le
refuse de nouveau, en proposant WhatsApp quand il est en service, sinon l'e-mail.

## Règles métier

- R1 — Un SMS de code ne part que vers un portable du Tchad : « +235 » suivi de 8 chiffres, qui ne
  commencent pas par un début de fixe (`22`, FEAT-024-Q05).
- R2 — Numéro étranger : refus 422 `SMS_FOREIGN_NUMBER` avec le message suivant, selon que WhatsApp
  est en service (`GET /auth/methods`) :
  - avec WhatsApp : « Le code par SMS n'est envoyé qu'aux numéros du Tchad. Avec un numéro étranger,
    connectez-vous par WhatsApp ou recevez le code par e-mail. » _(v2, 2026-11-26, FEAT-023 : par
    WhatsApp le client envoie le code, il n'en reçoit pas)_ ;
  - sans WhatsApp : « Le code par SMS n'est envoyé qu'aux numéros du Tchad. Avec un numéro étranger,
    recevez le code par e-mail. »
- R3 — Fixe du Tchad : refus 422 `PHONE_FIXED_LINE` avec « Ce numéro est un fixe : indiquez un
  numéro de portable (ex. 66 12 34 56). »
- R4 — Le refus vient avant tout le reste : avant l'arrêt du SMS (503), avant les compteurs de
  demandes, avant tout enregistrement. Rien ne part, rien ne se compte.
- R5 — Toutes les demandes de SMS passent par là :
  - la connexion par code (`POST /auth/otp/request`, y compris la connexion de l'équipe, FEAT-021) ;
  - le code d'un nouvel appareil (`POST /auth/password/challenge/send`, canal `sms`) ;
  - la confirmation du numéro dans « Mon profil » (`POST /me/phone/request`).
- R6 — La liste des moyens d'un nouvel appareil (`channels` de `POST /auth/password/login`) ne
  propose pas le SMS quand le numéro confirmé du compte n'est pas un portable du Tchad. L'e-mail
  reste proposé, et WhatsApp aussi quand il est en service.
- R7 — WhatsApp n'a pas de règle de pays : un numéro étranger y garde ses droits (FEAT-024-Q01).
- R8 — Écran : quand le numéro tapé pour un SMS est étranger ou fixe, le message de R2 ou R3
  s'affiche sous le champ et rien n'est envoyé. Il en va de même dans « Mon profil » : le bouton
  « SMS » est grisé, avec « SMS : numéros du Tchad seulement », quand le numéro du compte n'est pas
  un portable du Tchad.

## Scénarios

### SPEC-024-01-SC01 — un numéro étranger ne reçoit pas de SMS

Critères : FEAT-024-AC02, FEAT-024-AC08

- **Étant donné** le SMS en service, WhatsApp hors service
- **Quand** `POST /auth/otp/request` arrive avec `+33612345678` (but `login`)
- **Alors** 422 `SMS_FOREIGN_NUMBER` avec « Le code par SMS n'est envoyé qu'aux numéros du Tchad.
  Avec un numéro étranger, recevez le code par e-mail. » ; aucun code n'est enregistré, aucun SMS
  ne part, le compteur du numéro n'a pas bougé

### SPEC-024-01-SC02 — avec WhatsApp en service, le message le propose

Critères : FEAT-024-AC02

- **Étant donné** WhatsApp en service
- **Quand** la même demande arrive
- **Alors** le message dit « … connectez-vous par WhatsApp ou recevez le code par e-mail. »

### SPEC-024-01-SC03 — un fixe du Tchad ne reçoit pas de SMS

Critères : FEAT-024-AC02, FEAT-024-AC08

- **Étant donné** le SMS en service
- **Quand** une demande arrive pour `+23522512345`
- **Alors** 422 `PHONE_FIXED_LINE` avec « Ce numéro est un fixe : indiquez un numéro de portable
  (ex. 66 12 34 56). » ; rien n'est enregistré ni envoyé

### SPEC-024-01-SC04 — un portable du Tchad reçoit son SMS comme avant

Critères : FEAT-024-AC02

- **Étant donné** le SMS en service
- **Quand** une demande arrive pour `66 12 34 56`
- **Alors** le code part par SMS vers `+23566123456`, comme aujourd'hui

### SPEC-024-01-SC05 — nouvel appareil d'un compte au numéro étranger

Critères : FEAT-024-AC02

- **Étant donné** un compte dont le numéro confirmé est `+33612345678`, le SMS en service
- **Quand** il se connecte par mot de passe depuis un nouvel appareil, puis demande quand même le
  SMS
- **Alors** la liste des moyens propose l'e-mail mais pas le SMS ; la demande de SMS reçoit 422
  `SMS_FOREIGN_NUMBER`

### SPEC-024-01-SC06 — l'écran arrête la demande avant l'envoi

Critères : FEAT-024-AC02

- **Étant donné** l'écran de connexion (site, application client, console, application livreur),
  « recevoir un code par SMS »
- **Quand** il tape `+33 6 12 34 56 78`, puis `22 51 23 45`
- **Alors** le message de R2, puis celui de R3, s'affiche sous le champ, et aucune requête ne part

## Erreurs et cas limites

- Le SMS arrêté (`SMS_PROVIDER=disabled`) : un numéro étranger ou fixe reçoit le refus de R2 ou R3,
  plus utile que le 503 ; un portable du Tchad garde le 503 `SMS_UNAVAILABLE` de FEAT-008.
- Un numéro mal formé reste refusé par la validation existante (422 `VALIDATION_ERROR`).
- La vérification d'un code par SMS ne change pas : aucun code n'a pu partir vers ces numéros.

## Contrats API et données

- Nouveaux codes d'erreur dans `ApiErrorCode` (_nouveau_) :
  - `SMS_FOREIGN_NUMBER` (422) ;
  - `PHONE_FIXED_LINE` (422, partagé avec SPEC-024-02).
- Pour `POST /auth/otp/request`, `details: [{ path: 'phone', message }]` place le message sous le
  champ.
- Les routes et leurs champs ne changent pas.
- Données : aucune.
- Marché : `LAUNCH_MARKET.fixedLinePrefixes = ['22']` (_nouveau_, `@djafat/config`).

« Mon profil », le bouton grisé garde un nom accessible qui dit pourquoi.
