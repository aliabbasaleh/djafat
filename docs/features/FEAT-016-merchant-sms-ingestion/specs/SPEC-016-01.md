# SPEC-016-01 — Lire un SMS d'opérateur

## Comportement observable

Fonctions pures (`apps/api/src/modules/payments/sms-receipt-parser.ts`) : `verifyGatewaySignature`, `parseOperatorSms`, `balanceIsContinuous`.

## Règles métier

- R1 — Signature = HMAC-SHA256 de `${horodatage}.${corps brut}` avec le secret du téléphone ; horodatage à ±5 minutes ; comparaison à temps constant.
- R2 — Un SMS n'est lu que si son expéditeur est dans la liste de l'opérateur et qu'un modèle versionné le reconnaît ; il en sort montant, numéro de l'expéditeur, numéro de transaction et solde.
- R3 — Continuité : nouveau solde = ancien solde + montant, quand les deux sont connus.

## Scénarios

### SPEC-016-01-SC01 — signature

Critères : FEAT-016-AC01

- **Étant donné** un corps signé par le téléphone
- **Quand** on vérifie la signature
- **Alors** acceptée ; refusée si le corps, le secret ou l'horodatage (trop ancien) change

### SPEC-016-01-SC02 — SMS de transfert

Critères : FEAT-016-AC02

- **Étant donné** un SMS « Vous avez reçu … » de l'expéditeur Airtel
- **Quand** on le lit
- **Alors** montant, expéditeur, numéro de transaction, solde et modèle utilisé

### SPEC-016-01-SC03 — autre expéditeur ou texte inconnu

Critères : FEAT-016-AC04

- **Étant donné** le même texte d'un autre expéditeur, ou une publicité de l'opérateur
- **Quand** on le lit
- **Alors** ignoré, avec le motif

### SPEC-016-01-SC04 — continuité du solde

Critères : FEAT-016-AC03

- **Étant donné** un ancien solde, un montant et un nouveau solde
- **Quand** on vérifie
- **Alors** cohérent seulement si nouveau = ancien + montant ; sans référence ou sans solde, accepté

## Erreurs et cas limites

Montant nul ou absent : non reconnu.
