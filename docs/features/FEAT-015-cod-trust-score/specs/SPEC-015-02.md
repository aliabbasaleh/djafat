# SPEC-015-02 — Appliquer le plafond d'espèces

## Comportement observable

- `POST /v1/payments` avec un moyen `collectedOnDelivery` : 409 `COD_LIMIT` si le total dépasse le plafond du client.
- `GET /v1/payments/methods-for-order/:id` : ce moyen n'est pas listé dans ce cas.
- Contexte de course du livreur : `customerIsNew` ; étiquette « Nouveau client — appelez-le avant de partir ».

## Règles métier

- R1 — Faits lus par `OrderAmountPort.getCustomerTrustSignals` : commandes livrées, absences (historique `delivery.failed`), annulations depuis `courier_assigned`/`picked_up`/`on_the_way`, ancienneté, téléphone vérifié.
- R2 — Plafonds : réglages `cod_cap_t1_minor` (10 000), `cod_cap_t2_minor` (25 000), `cod_cap_t3_minor` (60 000).
- R3 — Une commande prise par le standardiste marque le numéro comme vérifié.

## Scénarios

### SPEC-015-02-SC01 — plafond d'un nouveau client

Critères : FEAT-015-AC02

- **Étant donné** un nouveau client de jour
- **Quand** il paie 10 000 puis 10 001 en espèces
- **Alors** autorisé puis refusé

### SPEC-015-02-SC02 — deux absences

Critères : FEAT-015-AC03

- **Étant donné** un client absent deux fois
- **Quand** il veut payer 1 000 en espèces
- **Alors** refusé, plafond 0

### SPEC-015-02-SC03 — refus et masquage

Critères : FEAT-015-AC02

- **Étant donné** un client au-delà de son plafond
- **Quand** il paie en espèces, puis demande les moyens de paiement
- **Alors** 409 `COD_LIMIT`, aucun `payment.on_delivery` ; seul le mobile money est listé

### SPEC-015-02-SC04 — client de confiance et prépayé

Critères : FEAT-015-AC02

- **Étant donné** un client T2, puis un client T0 qui paie d'avance
- **Quand** ils paient
- **Alors** les espèces passent pour le premier ; le prépayé n'est jamais limité

### SPEC-015-02-SC05 — parcours réel [evidence: manual]

Critères : FEAT-015-AC02, FEAT-015-AC03, FEAT-015-AC04

- **Étant donné** l'API réelle
- **Quand** un nouveau client, puis un client absent deux fois, commandent
- **Alors** voir `e2e-demo.md`

## Erreurs et cas limites

409 `COD_LIMIT` avec le plafond dans le message (0 = espèces indisponibles).
