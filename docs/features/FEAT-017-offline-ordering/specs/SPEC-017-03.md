# SPEC-017-03 — Le panier quand la connexion coupe

## Comportement observable

`/panier` : une clé courte (12 caractères) par tentative de commande, gardée
pendant les nouveaux essais. Coupure réseau ou erreur serveur : « Connexion
instable — nouvel essai dans N s » (2, 5, 12 s). Toujours en échec : encadré
« Pas de connexion Internet ? » avec le choix espèces / Airtel et les boutons
WhatsApp (`https://wa.me/…?text=`), SMS (`sms:…?body=`), appel (`tel:`).

## Règles métier

- R1 — Seules les coupures et les erreurs serveur sont réessayées ; un refus
  (panier vide, adresse supprimée…) s'affiche tout de suite et oublie la clé.
- R2 — Le bouton devient « Réessayer l'envoi par Internet », même clé.

## Scénarios

### SPEC-017-03-SC01 — message prêt

Critères : FEAT-017-AC05

- **Étant donné** un panier et une adresse
- **Quand** l'encadré est construit
- **Alors** le message est relu par le serveur à l'identique, avec la même clé, et les liens visent le numéro DJAFAT

### SPEC-017-03-SC02 — quoi réessayer

Critères : FEAT-017-AC05

- **Étant donné** une erreur réseau, 503, ou 409
- **Quand** l'envoi échoue
- **Alors** seules les deux premières sont réessayées

### SPEC-017-03-SC03 — écran réel [evidence: manual]

Critères : FEAT-017-AC05

- **Étant donné** le site réel et l'API coupée au moment de commander
- **Quand** le client appuie sur « Commander »
- **Alors** nouveaux essais puis encadré ; voir FEAT-017-VIS01

## Erreurs et cas limites

Numéro DJAFAT non configuré : l'encadré dit de réessayer, sans boutons.

## Contrats API et données

`POST /v1/orders` inchangé ; la clé `Idempotency-Key` devient courte (12 caractères).

## Autorisations
