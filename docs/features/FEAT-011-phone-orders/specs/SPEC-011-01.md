# SPEC-011-01 — Créer une commande pour un client qui appelle

## Comportement observable

- `POST /v1/admin/phone-orders` (en-tête `Idempotency-Key` obligatoire) avec
  `{ customerPhone, customerName?, items: [{ productId, quantity, selectedOptionIds? }], address: { quartier, landmark, street?, instructions?, coordinates? } }`
  → 201 `{ status, customer: { id, isNew }, order }`.
- La commande est en `placed` dès la réponse (paiement à la livraison), visible
  par le restaurant et dans la liste des commandes de l'admin.
- Écran admin `/admin/phone-order`.

## Règles métier

- R1 — Le client est retrouvé par son numéro ou créé (rôle `customer`) ; son nom n'est écrit que s'il n'en a pas.
- R2 — L'adresse est réutilisée si une adresse identique (quartier, repère, rue, point) existe déjà dans son carnet.
- R3 — Le panier du client est vidé puis rempli avec les plats demandés ; la commande est créée par `OrdersService.createOrder` (prix et ouverture vérifiés par le serveur).
- R4 — Le paiement est créé avec le moyen dont la capacité est `collectedOnDelivery` ; aucun nom de fournisseur n'est écrit en dur.
- R5 — Une trace d'audit `ORDER_PLACED_BY_PHONE` (standardiste, commande, client) est écrite à la création.

## Scénarios

### SPEC-011-01-SC01 — nouveau client

Critères : FEAT-011-AC01, FEAT-011-AC02, FEAT-011-AC04

- **Étant donné** un numéro inconnu
- **Quand** le standardiste envoie la commande
- **Alors** le compte, l'adresse, la commande et un paiement à la livraison sont créés, et l'audit est écrit

### SPEC-011-01-SC02 — client connu, même adresse

Critères : FEAT-011-AC01

- **Étant donné** un client qui a déjà un nom et cette adresse
- **Quand** il rappelle
- **Alors** son nom n'est pas changé et l'adresse n'est pas dupliquée

### SPEC-011-01-SC03 — aucun paiement à la livraison possible

Critères : FEAT-011-AC02

- **Étant donné** que le paiement à la livraison n'est pas activé pour cette commande
- **Quand** le standardiste envoie la commande
- **Alors** 409 `PAYMENT_METHOD_UNAVAILABLE`, aucun paiement créé

### SPEC-011-01-SC04 — double envoi

Critères : FEAT-011-AC03

- **Étant donné** une commande déjà passée avec une clé
- **Quand** la même clé est renvoyée (double clic, nouvelle tentative)
- **Alors** la même commande est renvoyée, sans second paiement

### SPEC-011-01-SC05 — écran de l'admin [evidence: manual]

Critères : FEAT-011-AC05

- **Étant donné** un standardiste connecté à l'admin
- **Quand** il remplit l'écran « Commande par téléphone » et valide
- **Alors** il voit le code de la commande ; voir `e2e-demo.md`

## Erreurs et cas limites

Restaurant fermé : 409 `RESTAURANT_CLOSED` (inchangé). Plat indisponible : erreur du panier (inchangée). Numéro invalide : 422.

## Contrats API et données
